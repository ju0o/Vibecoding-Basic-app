## 학생 질문

- API는 프로그램인가요, 주소인가요?
- Frontend가 Backend와 어떻게 이야기하나요?
- “API 키”는 왜 함부로 올리면 안 되나요? (개념만)

## 지금 배우는 이유

FE와 BE를 나눴다면, 둘을 잇는 **약속(인터페이스)** 이 필요합니다. 나중에 날씨·지도·결제 같은 **외부 서비스**를 붙일 때도 같은 말이 나옵니다.

## 핵심 (교육 모델)

- **API (Application Programming Interface)** — 프로그램이 서로 요청·응답하기 위한 **약속된 창구**.
- 웹에서 흔히: 브라우저(또는 앱)가 **HTTP 요청**을 보내고, 서버가 **상태 코드 + 본문**으로 응답합니다.
- Day1 서버도 “파일 주세요” 요청에 HTML/CSS/JS를 주는 **아주 단순한 형태의 API/엔드포인트 비유**로 읽을 수 있습니다 (REST JSON API와 동일하지는 않음 — 교육 비유).
- **API 키·비밀**은 권한 증표에 가깝습니다. 채팅·깃허브 공개 저장소에 붙이지 않습니다 (이전 오류→AI 수업과 연결).

## 요청·응답 미니 모델

```text
클라이언트  →  요청 (무엇을, 어디로)  →  서버
클라이언트  ←  응답 (성공/실패, 데이터)  ←  서버
```

## 실습

1. 인터랙티브에서 method/path를 바꿔 응답 메시지 관찰
2. 자기 말로 API 한 줄 정의
3. AI 요청 템플릿: “새 화면 문구 API가 아니라, 정적 파일 수정만”
