## 학생 질문

- Frontend는 화면인가요, 파일인가요?
- HTML/CSS/JS는 전부 Frontend인가요?
- Backend와 한 줄로 어떻게 구분하나요?

## 지금 배우는 이유

파일 연결을 알았으니, **역할 이름**을 붙입니다. AI·팀·문서에서 “프론트 고쳐 주세요”가 무엇을 가리키는지 이해할 수 있어야 합니다.

## 핵심 (교육 경계)

- **Frontend (FE)** — 사용자가 보는 쪽. 주로 **브라우저에서 실행·표시**되는 UI와 그 코드.
- Day1 샘플의 `index.html`, `style.css`, `main.js`는 **프론트엔드 쪽 자산**으로 읽으면 됩니다.
- 프레임워크(React 등)는 **나중 단계**. 지금은 “브라우저 UI 레이어” 개념이 목표입니다.
- Frontend ≠ “예쁘기만 하는 것” — **구조·스타일·상호작용**을 포함합니다.

## 흔한 오해

| 오해 | 교정 |
|---|---|
| Frontend = 디자인 툴 | 코드로 만드는 UI 레이어 |
| 모든 JS = Frontend | 서버에서 도는 JS도 있음 (Node 수업 참고) |
| Frontend만 있으면 앱 완성 | 저장·로그인 등은 보통 Backend/서비스 필요 |

## 실습

1. Day1 샘플 세 파일을 “Frontend 자산”으로 라벨 붙이기
2. 한 줄 정의: “Frontend는 ___ 에서 보이는 ___ 이다”
3. AI 요청: “프론트엔드 문구만 바꾸고 server.js는 건드리지 마세요”
