## 학생 질문

- 새로고침하면 왜 내 입력이 사라지나요?
- Database는 엑셀과 같나요?
- 모든 앱에 DB가 필요한가요?

## 지금 배우는 이유

Day1 샘플은 **파일로 화면을 보여 주는** 단계입니다. 메모·회원·저장이 필요해지면 **데이터가 브라우저 메모리 밖에도 남아야** 합니다. 제품 설치 전에 **왜 저장소가 등장하는지** 이해합니다.

## 핵심 (교육 모델)

- **Database (DB)** — 구조적으로 데이터를 **저장·조회·갱신**하기 위한 저장소 (제품 이름은 다양).
- 브라우저만의 임시 상태 ≠ 서버/DB에 저장된 데이터.
- 파일(`json` 하나)로도 작은 저장은 가능하지만, 동시 접속·검색·안전성 요구가 커지면 DB를 쓰는 경우가 많습니다 (**패턴**, 만능 법칙 아님).
- SQL/NoSQL, Firebase, Supabase, Neon, MongoDB 등은 **선택지**. 이 수업은 특정 제품을 표준으로 두지 않습니다. 가격·무료 범위는 공식 문서 확인 후에만.

## Day1과의 거리

| 단계 | 데이터 |
|---|---|
| Day1 샘플 | 코드 파일에 적힌 문구 (배포물 자체) |
| 브라우저 변수 | 새로고침 시 사라질 수 있음 |
| Database | 앱을 다시 열어도 **의도적으로 유지** |

## 실습

1. 인터랙티브에서 “메모리만 / 저장소” 토글 후 새로고침 시뮬레이션
2. “내가 만들고 싶은 앱에 저장이 필요한가?” Yes/No와 이유 한 줄
3. AI 요청: “DB 제품 추천 말고, 저장이 필요한 데이터 목록만 정리해 주세요”
