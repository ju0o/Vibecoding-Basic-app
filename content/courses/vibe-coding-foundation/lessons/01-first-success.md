### 추천 방법 (특정 유료 도구에 묶이지 않음)

**방법 A1 — HTML 파일 + 브라우저 (기본 추천)**

1. AI에게 아래처럼 요청합니다.

```text
초보자용으로, 외부 라이브러리 없이 단일 HTML 파일 하나만 만들어 주세요.
제목은 "나의 첫 바이브코딩", 본문에 "안녕하세요"를 넣고,
배경색은 아주 연한 파란색으로 해 주세요.
파일 내용 전체를 코드 블록으로 주세요.
```

2. AI가 준 **코드 전체**를 복사합니다.  
3. 메모장(Windows) 또는 TextEdit(macOS)을 엽니다.  
4. 붙여넣고 `hello-vibe.html` 같은 이름으로 저장합니다.  
   - Windows: 인코딩 UTF-8, 확장자가 정말 `.html`인지 확인  
5. 파일을 **브라우저로 엽니다** (더블클릭 또는 브라우저에 끌어다 놓기).  
6. 화면에 제목과 “안녕하세요”가 보이면 **첫 성공**입니다.

**방법 A2 — (선택) 이미 쓰는 AI의 미리보기**

일부 AI 제품은 채팅 안에서 미리보기를 보여 줍니다.  
있으면 써도 됩니다. **없어도 Path A는 A1으로 충분**합니다.  
계정·유료 플랜을 새로 강요하지 마세요.

### 기대 결과

- 브라우저에 내 문구가 보인다

## 결과 수정해보기 (Experience 연장)

AI에게 **한 가지**만 바꿔 달라고 합니다. 예:


이것이 바이브코딩의 작은 리듬입니다.

```text
요청 → 결과 확인 → 수정 요청 → 다시 확인
```

## 방금 무슨 일이 일어났는가 (Question → Theory)

### 바이브코딩이란? 일반 코딩과 뭐가 다른가?

| | 전통적인 입문 코딩 감각 | 오늘 한 바이브코딩 감각 |
|---|---|---|
| 시작 | 빈 파일에 문법을 직접 많이 씀 | 원하는 **결과**를 말로 요청 |
| 속도 | 문법을 외우는 데 시간이 감 | 초안이 빨리 나옴 |
| 사람 역할 | 모든 줄을 처음부터 작성 | **목표·확인·수정·설명**을 붙잡음 |

교육용 바이브코딩은 “코드를 절대 안 본다”가 아닙니다.  
**AI가 만든 것을 실행하고, 바꾸고, 왜 그런지 조금씩 설명**하는 방식입니다.

### AI에게 말했는데 왜 파일이 만들어지나?

AI는 글(코드 포함)을 생성할 수 있습니다.  
당신이 그 글을 **파일로 저장**하거나, 어떤 도구가 **프로젝트 폴더에 써 주면** 파일이 됩니다.  
마법이 아니라 **생성 → 저장/적용 → 실행 환경**의 연결입니다.

### 왜 AI마다 프로젝트 구조가 다를 수 있나?

AI와 도구는 **기본 템플릿·습관·당신이 준 지시**가 다릅니다.  
그래서 폴더 이름·프레임워크 선택이 달라질 수 있습니다.  
Day 1에서는 “틀린 것”이 아니라 **다른 출발점**으로 이해합니다.  
중요한 것은 **실행해서 확인**하는 습관입니다.

## IDE와 AI IDE

### IDE는 무엇인가? 왜 필요한가?

**IDE(통합 개발 환경)** 는 대략 이런 **작업 공간**입니다.

- 폴더·파일을 열고  
- 코드를 고치고  
- (많은 경우) 터미널·확장 기능으로 실행·검사  

브라우저만으로도 Path A는 됩니다.  
다만 파일이 많아지면 **탐색기 + 편집 + 터미널**이 한곳에 있는 편이 편합니다. 그게 IDE를 쓰는 이유입니다.

### VS Code는 무엇인가?

**Visual Studio Code(VS Code)** 는 널리 쓰이는 **무료 코드 편집기**입니다.  
공식 설치: [https://code.visualstudio.com/Download](https://code.visualstudio.com/Download)  
(문서: [VS Code Docs](https://code.visualstudio.com/docs))

**필수 종교가 아닙니다.** 다른 편집기를 써도 “IDE 역할”은 같습니다.  
이 수업에서는 예시로 VS Code를 씁니다.

### AI IDE는 일반 IDE와 무엇이 다른가?

| | 일반 IDE | AI IDE / AI 코딩 도구 |
|---|---|---|
| 기본 | 사람이 파일을 편집 | 편집 + **대화로 수정·생성** 지원 |
| 예 | VS Code 기본 | VS Code + 확장, 또는 AI 기능이 강한 편집기 등 |

제품 이름·가격·기능은 **자주 바뀝니다.**  
오늘은 특정 제품을 외우지 말고,  
“**말을 걸어 코드를 바꿀 수 있는 작업 공간**” 정도로 이해하면 됩니다.

## `node -v` 와 `npm -v` — 무엇을 확인하나?

터미널에 입력 후 Enter:

```bash
node -v
npm -v
```

| 명령 | 의미 |
|---|---|
| `node -v` | Node.js가 설치되어 있는지, **버전 문자열**이 나오는지 |
| `npm -v` | npm(패키지 관리 도구)이 함께 쓰일 수 있는지 |

버전이 숫자로 나오면 성공입니다.  
`command not found` / 인식할 수 없습니다 → 설치·PATH·터미널 재시작을 다시 봅니다.

npm은 Node 설치에 **함께 제공되는 경우가 많으며**, 프로젝트에 필요한 라이브러리를 받아 관리하는 데 쓰입니다.  
(공식 소개: [Node.js — npm package manager](https://nodejs.org/learn/getting-started/an-introduction-to-the-npm-package-manager))

## 첫 프로젝트 실행 (Path B · 안내에 따라)

로컬에서 “서버를 켠다”는 감각을 익힙니다. **프로젝트마다 명령이 다를 수 있습니다.**

### 공통 순서

1. **제공된 실습 프로젝트** 또는 AI가 만든 프로젝트 폴더를 준비합니다.  
   - 강사/코스가 zip을 주면 압축 해제  
   - 없으면 AI에게: “초보자용 Vite 또는 아주 단순한 Node 정적 서버 예제” 등 **한 가지**만 요청 (강사 안내에 따르기)  
2. VS Code에서 **파일 → 폴더 열기**로 그 폴더를 엽니다.  
3. 통합 터미널을 엽니다. 현재 폴더가 프로젝트 루트인지 확인합니다.  
4. `package.json` 파일이 보이는지 탐색기에서 확인합니다.  
5. 의존성이 필요하면:

```bash
npm install
```

6. `package.json`의 `scripts`에 `dev`가 있으면:

```bash
npm run dev
```

없으면 강사 안내에 적힌 명령(예: `npm start`)을 사용합니다.  
**없는 스크립트 이름을 추측해 외우지 마세요.**

7. 터미널에 `http://localhost:...` 주소가 보이면, 브라우저에 그 주소를 엽니다.  
8. 페이지가 보이면 Path B 실행 성공입니다.  
9. 끝낼 때 터미널에서 `Ctrl+C` 로 서버를 종료하는 경우가 많습니다.

## package.json, src, npm 이해하기 (아주 기본)

| 이름 | 초보 한 줄 |
|---|---|
| **package.json** | 이 프로젝트의 **이름표 + 의존성 목록 + 실행 스크립트 메모** |
| **npm install** | package.json(과 lock)을 보고 **필요한 패키지를 받아 설치** |
| **npm run dev** | package.json에 적힌 **`dev` 스크립트**를 실행 (있으면) |
| **src** | 많은 템플릿이 **소스 코드**를 모아 두는 폴더 이름 (항상 필수는 아님) |

공식: scripts는 `package.json`의 `scripts` 필드에 정의되고 `npm run <이름>`으로 실행합니다.  
([npm Docs — scripts](https://docs.npmjs.com/cli/v11/using-npm/scripts))

## 자주 발생하는 오류

| 증상 | 먼저 볼 것 |
|---|---|
| `node` / `npm` 을 찾을 수 없음 | 설치 여부, **터미널 재시작**, PATH |
| `npm install` 실패 | 인터넷, 회사 프록시, 잘못된 폴더 |
| `Missing script: "dev"` | 이 프로젝트에 `dev` 스크립트가 없음 → package.json 확인 |
| `EADDRINUSE` / 포트 사용 중 | 이미 서버가 켜져 있음 · 다른 포트 · 이전 터미널 종료 |
| 페이지가 안 열림 | 주소 오타, 서버가 꺼짐, 방화벽 |
| HTML만 열었는데 CSS가 안 입음 | 파일 경로·상대 경로 (Path A 단순 HTML은 인라인이 안전) |
