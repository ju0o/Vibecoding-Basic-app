## 학생 질문

- 큰 기능을 한 번에 시키면 왜 망가지나요?
- 어느 크기가 “작은 작업”인가요?
- AI에게 어떻게 쪼개서 요청하나요?

## Why Now

좋은 요청·프롬프트·컨텍스트·관련 파일을 배웠습니다.  
그래도 “로그인 있는 메모 앱 전부”처럼 **한 덩어리**로 시키면 범위가 폭발합니다.

## 핵심 (교육 패턴)

1. 큰 목표를 적는다.  
2. **검증 가능한 조각**으로 나눈다 (각 조각 = 성공 기준 1개).  
3. 의존 순서를 정한다 (화면 → 입력 → 저장은 나중 등).  
4. 한 조각씩 AI에 요청하고 **확인 후** 다음.  
5. “나중에” 할 일을 명시해 범위를 지킨다.

Day1 앵커: “제목 문구 변경”은 작은 작업. “회원 시스템 전체”는 큰 작업.

## 나쁜 분해 vs 좋은 분해

| 나쁜 예 | 나은 예 |
|---|---|
| 앱 완성해 | 1) 정적 제목 변경 2) 입력 칸 표시 3) 저장은 다음 |
| 한꺼번에 UI+DB+로그인 | UI 문구 → 검증 → 그다음 API 설계 메모 |

## 실습

1. 목표: “메모 앱”을 적는다.  
2. 인터랙티브에서 포함할 단계 토글.  
3. 내 목표로 3단계 이하 + 각 성공 기준 1줄.  
4. **실패 예:** 단계 6개 이상, 기준 없음.  
5. **복구:** 이번 주에 확인 가능한 것만 남긴다.
