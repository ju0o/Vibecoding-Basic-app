## 0. 수업 목표 (강사 메모)

학생이 **이론 시험**을 통과하는 날이 아니다.

1. Path A로 **화면 성공**을 맛본다.  
2. “요청 → 확인 → 수정” 리듬을 몸에 익힌다.  
3. Path B로 도구 문을 연다 (시간 가변 · 실패 가능 · 재도전 OK).  
4. Complete = 출석이 아니라 **can-do** (Outcome Contract).

말하세요:

> “오늘은 많이 아는 날이 아니라, **한 번 성공하고 도구를 켜 보는 날**입니다.”

---

## 1. 오프닝 (3–5분)

### 말할 말

- 여러분 중 코딩을 ‘문법 암기’로 만난 분이 많을 수 있습니다.  
- 오늘은 **빈 문법 시험지**부터 시작하지 않습니다.  
- AI에게 부탁해 **작은 페이지**를 만들고, 그다음에야 “이게 왜 됐지?”를 묻습니다.

### 질문 시점

- “지금 코딩이 무섭다면, 손 들어 볼까요?” (분위기용, 강제 X)  
- “10분 안에 ‘내가 시킨 화면’을 보는 게 목표입니다.”

### 예상 반응

| 반응 | 대응 |
|---|---|
| “설치부터 해야죠?” | “설치는 Path B. 먼저 Path A로 성공합니다.” |
| “어떤 AI 써야 해요?” | “이미 쓰는 것. 유료 필수 아님. HTML만 받으면 됨.” |
| “저는 개발자 아닙니다” | “그래서 오늘 온 겁니다. 따라 하면 됩니다.” |

## 2. Path A 라이브 (10–15분)

### 진행

1. 프롬프트를 화면/채팅에 공유 (학생 자료와 동일).  
2. 강사가 **한 번** 시연: 저장 → 브라우저.  
3. 학생이 동일 수행.  
4. 수정 요청 1회 (제목/문장).

### 확인할 포인트

- [ ] 파일이 `.txt`로 저장되지 않았는가  
- [ ] 브라우저에 빈 화면이면 코드 전체 복사 여부  
- [ ] “성공!”을 크게 인정 (동기)

### 혼동 표현 교정

| 학생이 말하는 말 | 부드럽게 고치기 |
|---|---|
| “AI가 해킹해서 파일을 만들었다” | “글을 생성했고, **우리가 저장**해서 파일이 됐어요.” |
| “코딩을 안 해도 되는 거죠?” | “초안은 AI, **확인·수정·설명**은 우리 몫이에요.” |
| “HTML이 프로그래밍 언어 전체인가요?” | “오늘은 **화면 한 장**을 여는 수단이에요. 전체가 아니에요.” |

### 시간 조정

- 빠른 반: 수정 요청 2회, 색 변경 실험  
- 느린 반: 강사 제공 **완성 HTML** 배포 후 “저장·열기·한 줄 수정”만

## 3. 짧은 Theory — 바이브코딩 · 파일 · 구조 (8–12분)

### 말할 말

- 표(전통 vs 바이브) 그리기  
- “마법이 아니라 생성 → 저장 → 실행”  
- “AI마다 폴더가 다른 건 버그가 아니라 출발점이 다른 것”

### 질문 시점

- “방금 성공을 **한 문장**으로 이웃에게 설명해 볼까요?”  
- “코드를 한 줄도 안 보면 위험할 수 있는 이유는?” (검증·보안 씨앗, 깊게 X)

### 예상 반응

- “결국 코딩이잖아요” → “맞아요. 다만 **시작 방식**이 달라졌어요.”

## 4. IDE / VS Code / AI IDE (5–8분)

### 말할 말

- IDE = 작업 공간  
- VS Code = 예시 무료 편집기 (필수 종교 아님)  
- AI IDE = 편집 + 대화 수정 (제품명·가격 가변 · 단정 금지)

### 확인할 포인트

- 학생이 “내 PC에 편집기가 있는지”만 확인해도 OK

---

## 5. Path B 랩 (20–60분+ · 가변)

### 사전 공지 (필수)

> “Path B는 10분 보장이 아닙니다. 회사 PC는 설치가 막힐 수 있어요.  
> 막혀도 Path A 성공은 남습니다. 기록하고 다음에 이어가요.”

### 순서 큐 카드

1. VS Code 유무  
2. Node LTS 설치 (공식 사이트)  
3. 터미널 새 창  
4. `node -v` / `npm -v`  
5. 폴더 열기  
6. `npm install` (프로젝트 있을 때)  
7. `npm run dev` 또는 안내 스크립트  
8. localhost 브라우저  

### 설치 오류 대응 치트시트

| 오류 | 강사 행동 |
|---|---|
| node not found | 설치 확인, **터미널 재시작**, PATH 스크린샷 |
| 권한 없음 | Path B 보류 기록 · IT 요청 문장 제공 · Path A 심화 |
| npm install 네트워크 | 모바일 핫스팟 시험 · 회사 프록시는 IT |
| Missing script dev | package.json 함께 읽기 · 있는 스크립트만 실행 |
| 포트 충돌 | Ctrl+C, 다른 포트, 작업 관리자에서 node 종료(주의) |

### 실습 중 순회 포인트

- [ ] 프로젝트 **루트**에서 명령하는가  
- [ ] 버전 출력을 사진/메모로 남겼는가  
- [ ] 오류를 **부끄러워하지 않고** 복사하는가  

### 시간 조정안

| 남은 시간 | 전략 |
|---|---|
| 15분 | 버전 확인까지만 = Path B 최소 성공 |
| 40분 | install + run 시도 |
| 막힌 다수 | 페어 프로그래밍 · 강사 머신 시연 + 학생은 명령만 타이핑 |

## 6. package.json / src / npm (7–10분 · 실습 직후)

### 말할 말

- package.json = 이름표 + 의존성 + 스크립트 메모  
- npm install = 재료 사오기  
- npm run dev = “dev라고 적힌 레시피 실행”  
- src = 흔한 재료 칸 (없어도 됨)

### 질문

- “`npm run pizza` 는 왜 실패할 수 있죠?” → 스크립트에 없어서

외우기 금지: **프로젝트마다 다르다는 것**을 강조.

## 7. 오류 → AI (5분)

라이브로 일부러 틀린 명령(`npm run deev`) → 메시지 복사 → AI 질문 템플릿 사용.

말하세요:

> “오류는 실패 증명서가 아니라 **AI에게 줄 재료**입니다.”
