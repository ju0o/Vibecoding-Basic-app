## 오늘 배울 것

사용자가 버튼을 눌렀을 때 화면 뒤에서 API와 DB가 어떤 일을 하는지 배웁니다.

요청, 응답, 상태 코드, 데이터 저장을 하나의 흐름으로 연결합니다.

## 한 줄 정의

API는 프론트엔드와 백엔드가 데이터를 주고받는 약속이고, DB는 서비스 데이터가 오래 저장되는 장소입니다.

## 쉬운 비유

식당에서 주문하는 장면을 떠올려봅시다. 손님이 주문서를 내는 것이 요청이고, 주방이 음식을 내주는 것이 응답입니다.

API는 주문서 양식이고, DB는 재료와 주문 기록이 보관되는 창고입니다.

## 왜 생겼는가

웹 서비스는 단순히 화면만 보여주지 않습니다. 회원 정보, 결제 내역, 게시글, 학습 진행률처럼 계속 저장되어야 하는 데이터가 있습니다.

프론트엔드가 DB에 직접 접근하면 보안과 규칙 관리가 어렵습니다. 그래서 백엔드 API가 중간에서 요청을 검사하고 필요한 데이터만 주고받게 합니다.

## 어떤 문제를 해결하는가

- 프론트엔드와 백엔드의 역할을 분리합니다.
- 데이터 접근 규칙과 보안을 서버에서 관리합니다.
- 여러 화면이나 앱이 같은 API를 사용할 수 있습니다.
- 실패 이유를 상태 코드와 메시지로 전달할 수 있습니다.

## 핵심 개념

요청은 클라이언트가 서버에 보내는 질문이나 명령입니다. 예를 들어 "이 사용자의 진행률을 저장해줘"가 요청입니다.

응답은 서버가 돌려주는 결과입니다. 성공 데이터일 수도 있고, 실패 이유일 수도 있습니다.

상태 코드는 응답의 큰 의미를 숫자로 알려줍니다. 200은 성공, 400은 요청 문제, 401은 인증 문제, 500은 서버 문제입니다.

DB는 진짜 기록을 보관합니다. 화면에 보이는 상태와 DB에 저장된 상태가 항상 같은 것은 아니므로 동기화가 필요합니다.

## 실제 예시

사용자가 강의 체크리스트를 완료하면 프론트엔드는 "이 항목을 완료 처리해줘"라는 요청을 보냅니다.

서버는 로그인한 사용자인지 확인하고 DB에 저장합니다. 성공하면 새 진행률을 응답하고, 실패하면 상태 코드와 오류 메시지를 줍니다.

## 코드 예시

```ts
type SaveProgressRequest = {
  readonly lessonSlug: string
  readonly completedItemIds: readonly string[]
}

async function saveProgress(request: SaveProgressRequest): Promise<Response> {
  return fetch("/api/progress", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(request),
  })
}
```

## AI 시대에서의 의미

AI에게 백엔드 작업을 요청할 때는 화면 요구사항만 말하면 부족합니다. 어떤 데이터를 저장하는지, 누가 접근할 수 있는지, 실패하면 무엇을 보여줄지 알려줘야 합니다.

AI가 만든 API는 반드시 상태 코드, 인증, 데이터 검증, 오류 처리를 확인해야 합니다.

## 자주 헷갈리는 것

API는 데이터베이스가 아닙니다. API는 통신 약속이고 DB는 저장소입니다.

프론트엔드 상태와 DB 상태도 다릅니다. 화면에서 체크된 것처럼 보여도 저장 요청이 실패하면 새로고침 후 사라질 수 있습니다.

## 실무에서 쓰는 방식

실무에서는 API 명세를 먼저 정합니다. 요청 형식, 응답 형식, 실패 상태, 권한 규칙을 문서화합니다.

그 다음 프론트엔드는 명세에 맞춰 요청하고, 백엔드는 요청을 검증해 DB와 통신합니다. 로그와 모니터링으로 실패를 추적합니다.

## 공부 체크리스트

- 요청과 응답의 방향을 설명할 수 있다.
- 상태 코드 200, 400, 401, 500을 구분할 수 있다.
- API와 DB의 역할 차이를 말할 수 있다.
