## 오늘 배울 것

웹 화면이 HTML, CSS, JavaScript로 나뉘어 만들어지는 이유를 배웁니다.

초보자가 화면을 볼 때 "어디가 구조이고, 어디가 스타일이고, 어디가 행동인지"를 구분하는 힘을 기르는 것이 목표입니다.

## 한 줄 정의

HTML은 구조, CSS는 모양, JavaScript는 행동을 담당하며 브라우저는 이 세 가지를 읽어 사용자가 보는 화면으로 바꿉니다.

## 쉬운 비유

웹 페이지를 가게라고 생각해봅시다. HTML은 진열대와 계산대의 위치, CSS는 인테리어와 간판, JavaScript는 문이 열리고 결제가 처리되는 행동입니다.

셋 중 하나만 있어도 완성된 가게처럼 느껴지지 않습니다.

## 왜 생겼는가

초기 웹은 문서를 공유하는 용도였습니다. 그래서 HTML은 문서 구조를 표현하는 데서 출발했습니다.

웹이 서비스와 앱으로 발전하면서 보기 좋은 배치가 필요해졌고 CSS가 중요해졌습니다. 이후 사용자가 클릭하고 입력하고 데이터를 주고받는 기능이 늘면서 JavaScript가 웹의 행동을 담당하게 되었습니다.

## 어떤 문제를 해결하는가

- 구조, 스타일, 행동을 분리해 수정하기 쉽게 합니다.
- 같은 구조에 다른 디자인을 입힐 수 있습니다.
- 사용자의 입력과 상태 변화에 반응하는 화면을 만들 수 있습니다.
- AI에게 요청할 때 문제 위치를 좁힐 수 있습니다.

## 핵심 개념

HTML은 의미를 담습니다. 제목은 제목으로, 버튼은 버튼으로, 링크는 링크로 적어야 합니다.

CSS는 배치와 시각적 위계를 만듭니다. 여백, 색상, 글꼴, 반응형 레이아웃이 여기에 들어갑니다.

JavaScript는 상태와 사건을 다룹니다. 클릭, 입력, 요청, 응답, 화면 업데이트가 여기에 속합니다.

브라우저는 이 파일들을 읽고 DOM이라는 화면 구조를 만든 뒤 스타일을 계산하고 사용자 행동을 연결합니다.

## 실제 예시

로그인 화면을 보면 이메일 입력칸과 비밀번호 입력칸은 HTML입니다.

입력칸의 둥근 모서리, 파란 로그인 버튼, 모바일에서 세로로 쌓이는 배치는 CSS입니다.

버튼을 눌렀을 때 서버에 요청하고 실패 메시지를 보여주는 동작은 JavaScript입니다.

## 코드 예시

```html
<form class="login-form">
  <label for="email">이메일</label>
  <input id="email" name="email" type="email" />
  <button type="submit">로그인</button>
</form>
```

```css
.login-form {
  display: grid;
  gap: 12px;
}
```

```js
document.querySelector(".login-form").addEventListener("submit", (event) => {
  event.preventDefault()
  console.log("로그인 요청을 보냅니다")
})
```

## AI 시대에서의 의미

AI에게 "버튼이 안 돼요"라고 말하면 원인이 HTML, CSS, JavaScript 중 어디인지 모호합니다.

"버튼은 보이지만 클릭해도 API 요청이 가지 않습니다"라고 말하면 JavaScript나 요청 흐름을 봐야 한다는 힌트가 생깁니다.

## 자주 헷갈리는 것

HTML은 단순히 글자를 보이게 하는 파일이 아닙니다. 화면의 의미와 접근성을 결정합니다.

CSS는 예쁘게 꾸미는 것만이 아닙니다. 사용자가 무엇을 먼저 봐야 하는지 정하는 정보 설계입니다.

JavaScript는 모든 문제의 답이 아닙니다. 단순 배치는 CSS로 해결하는 것이 더 낫습니다.

## 실무에서 쓰는 방식

실무에서는 컴포넌트 안에서도 구조, 스타일, 행동을 머릿속으로 구분합니다.

버그가 생기면 "요소가 없는가", "보이지만 가려졌는가", "클릭 이벤트가 연결되지 않았는가", "서버 응답이 실패했는가"처럼 층을 나눠 확인합니다.

## 공부 체크리스트

- 화면 요소를 HTML, CSS, JavaScript 역할로 나누어 설명할 수 있다.
- 브라우저가 파일을 읽어 화면을 만드는 흐름을 말할 수 있다.
- AI에게 문제 위치를 좁힌 요청을 작성할 수 있다.
