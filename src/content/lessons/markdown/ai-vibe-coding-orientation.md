## 오늘 배울 것

AI 바이브코딩을 "AI가 코드를 대신 짜주는 방식"이 아니라 "사람이 목표와 검증을 맡고 AI가 빠르게 시도하는 협업 방식"으로 이해합니다.

이 강의에서는 좋은 요청, 결과 검토, 반복 수정, 설명 연습이 왜 필요한지 먼저 잡습니다.

## 한 줄 정의

AI 바이브코딩은 AI에게 코딩을 맡기는 것이 아니라, 사람이 제품 목표와 판단 기준을 세우고 AI와 빠르게 구현, 검증, 개선을 반복하는 개발 학습 방식입니다.

## 쉬운 비유

처음 가는 도시에서 택시를 탄다고 생각해봅시다. 목적지와 경유지를 말하지 않으면 운전자는 움직일 수 있지만 원하는 곳에 데려다주지는 못합니다.

AI도 비슷합니다. "로그인 만들어줘"보다 "이메일과 비밀번호로 로그인하고, 실패하면 한국어 오류를 보여주고, 모바일에서도 버튼이 잘 보여야 해"가 훨씬 좋은 지시입니다.

## 왜 생겼는가

개발자는 점점 더 많은 도구, 프레임워크, 배포 환경, 보안 기준을 다뤄야 했습니다. 초보자는 작은 화면 하나를 만들려고 해도 HTML, CSS, JavaScript, 상태, API, DB, 배포를 동시에 만나게 됩니다.

AI 코딩 도구는 이 복잡한 진입 장벽을 낮추기 위해 등장했습니다. 하지만 도구가 빨라질수록 "무엇을 만들지", "맞게 되었는지", "왜 이렇게 했는지"를 판단하는 사람의 역할은 더 중요해졌습니다.

## 어떤 문제를 해결하는가

- 처음부터 모든 문법을 외워야 한다는 부담을 줄입니다.
- 막혔을 때 검색어를 몰라서 멈추는 시간을 줄입니다.
- 작은 기능을 빠르게 만들어 보고, 동작을 보며 배울 수 있게 합니다.
- 코드 설명, 오류 해석, 리팩터링 아이디어를 즉시 받을 수 있습니다.

## 핵심 개념

AI 바이브코딩의 핵심은 네 가지입니다.

첫째, 목표를 제품 행동으로 말합니다. "예쁘게"가 아니라 "초보자가 첫 강의를 바로 찾게"처럼 관찰 가능한 행동으로 말합니다.

둘째, 맥락을 줍니다. 현재 파일, 기술 스택, 사용자의 수준, 제한 조건을 알려줍니다.

셋째, 결과를 검증합니다. 실행, 화면 확인, 테스트, 코드 읽기를 통해 AI 결과를 그대로 믿지 않습니다.

넷째, 설명할 수 있게 만듭니다. 내가 남에게 설명할 수 없으면 아직 배운 것이 아닙니다.

## 실제 예시

나쁜 요청은 "회원가입 페이지 만들어줘"입니다. 범위도, 실패 조건도, 디자인 기준도 없습니다.

좋은 요청은 "Next.js와 TypeScript로 회원가입 페이지를 만들고, 이메일 형식 검사, 비밀번호 8자 이상 검사, 실패 메시지, 모바일 375px 화면 확인까지 포함해줘"입니다.

더 좋은 요청은 여기에 "초보자가 읽기 쉬운 컴포넌트 이름을 쓰고, 왜 이렇게 나눴는지 설명해줘"를 붙이는 것입니다.

## 코드 예시

```ts
type AiCodingRequest = {
  readonly goal: string
  readonly context: string
  readonly constraints: readonly string[]
  readonly verification: readonly string[]
}

const request: AiCodingRequest = {
  goal: "초보자가 첫 강의를 찾고 진행률을 확인하는 홈 화면 만들기",
  context: "Next.js, TypeScript, Tailwind CSS 기반 학습 사이트",
  constraints: ["모바일 반응형", "다크모드", "콘텐츠와 UI 분리"],
  verification: ["npm run build", "홈 화면에서 다음 강의 링크 클릭"],
}
```

## AI 시대에서의 의미

AI 시대의 개발자는 코드를 한 줄씩 모두 외우는 사람보다, 문제를 정확히 정의하고 결과를 검증하며 시스템을 설명할 수 있는 사람이 됩니다.

AI가 빠르게 초안을 만들수록 사람은 더 좋은 질문자, 리뷰어, 설계자가 되어야 합니다.

## 자주 헷갈리는 것

AI 바이브코딩은 대충 만드는 방식이 아닙니다. 오히려 빠르게 만들기 때문에 더 자주 확인해야 합니다.

또한 "프롬프트만 잘 쓰면 된다"도 아닙니다. 파일 구조, 테스트, 디자인, 배포, 보안까지 함께 봐야 실전 개발이 됩니다.

## 실무에서 쓰는 방식

실무에서는 먼저 작은 목표를 정합니다. 예를 들어 "강의 상세 페이지의 이전/다음 이동"처럼 끝이 보이는 단위로 나눕니다.

그 다음 AI에게 현재 구조와 완료 조건을 주고 구현하게 한 뒤, 직접 실행해보고 코드 리뷰를 합니다. 부족하면 "왜 틀렸는지"를 다시 맥락으로 넣어 수정합니다.

## 공부 체크리스트

- AI에게 맡길 일과 내가 판단할 일을 구분할 수 있다.
- 목표, 맥락, 제약, 검증을 포함한 요청을 작성할 수 있다.
- AI 결과를 실행과 설명으로 검증할 수 있다.
