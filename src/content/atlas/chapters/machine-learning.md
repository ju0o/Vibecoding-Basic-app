## 한 줄 정의

Machine Learning(머신러닝)은 사람이 모든 규칙을 직접 코딩하는 대신, **예시 데이터에서 패턴을 학습**해 새로운 입력에 대해 예측·분류하는 방법입니다.

## 왜 등장했는가

AI 목표를 “규칙 나열”로만 풀려 하면, 스팸·추천·인식처럼 입력이 무한히 다양한 영역에서 규칙이 감당되지 않습니다. 대신 “정답이 붙은 예시(또는 목표 신호)를 많이 주고, 모델이 내부 가중치를 조정하게 하자”는 접근이 필요합니다. (interpretation / educational_example)

## 이전 기술의 한계

순수 규칙 기반 시스템은 투명하지만, **예외가 늘수록 유지보수가 폭발**합니다. “비슷한 경우”를 사람이 일일이 정의하기도 어렵습니다. AI라는 목표만 있고 학습 방법이 없으면, 결국 더 많은 규칙을 쓰게 됩니다.

## 무엇을 해결했는가

ML은 **학습 데이터 → 모델 → 예측**이라는 반복 가능한 루프를 제공합니다. 장점: 데이터 분포 안의 패턴을 일반화. 한계: 데이터가 편향되면 결과도 편향되고, 분포 밖 입력에서는 실패할 수 있으며, “왜 그 예측인지”가 항상 설명되지는 않습니다. ML이 곧 Deep Learning은 아닙니다.

- 추천 시스템의 일부 구성 요소 (제품마다 다름)

## 대표 기업

ML 도구·클라우드 학습 플랫폼을 제공하는 기업이 많습니다. 이 챕터는 특정 벤더를 “정답 기업”으로 고르지 않습니다. 도구 선택 가이드는 공식 문서와 최신 정책을 확인하세요. (official_verified는 제품 문서 단위로 별도 확인)

## 대표 서비스

표 데이터 학습, AutoML, 학습 파이프라인 서비스 등이 있습니다. 서비스 이름보다 **학습 데이터 품질·평가 지표·배포 후 모니터링**이 실무 핵심입니다.

## 실제 프로젝트에서는 어떻게 사용하는가

바이브코딩에서도 “모델을 직접 학습”하지 않더라도 ML 개념이 나타납니다. 예: AI 도구가 비슷한 코드 예시를 참고하거나, 분류·추천 API를 호출할 때. 학습자 관점 체크리스트: (1) 무엇을 맞히려고 하는가 (2) 어떤 예시로 배웠는가 (3) 실패하면 어떻게 아는가. 검증 없이 예측을 사실로 쓰지 마세요.

## 실습

1. “사과/바나나 사진 분류”를 상상합니다.
2. 규칙 기반이라면 어떤 규칙을 쓸지 2개 적어 봅니다 (색, 모양…).
3. 그 규칙이 깨지는 예외(조명, 각도)를 적어 봅니다.
4. ML이라면 무엇이 “학습 데이터”가 되어야 하는지 한 문장으로 씁니다.
