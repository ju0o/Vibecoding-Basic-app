FRAMEWORK CHOICE

React와 Next.js는같은 출발점이지만맡는 범위가 다릅니다

React는 화면을 컴포넌트와 상태로 잘 만드는 라이브러리입니다. Next.js는 React 위에 페이지 주소, 서버 렌더링, API 지점, 프로젝트 구조를 얹은 프레임워크입니다.

REACT화면 안에서 값이 계속 바뀔 때예약, CRM, 채팅, 관리자 대시보드처럼 사용자가 계속 조작하는 화면.
NEXT.JS공개 URL과 서버 준비가 중요할 때쇼핑몰, 블로그, 랜딩, 기업 홈페이지처럼 검색·공유·배포가 중요한 서비스.
BACKEND백엔드 유무의 차이가 아닙니다React도 API/Firebase/Supabase와 연결합니다. Next.js는 그 연결 지점을 프로젝트 안에 더 체계적으로 둘 수 있습니다.

실제 서비스 화면을 열어 비교합니다

각 예시는 “도형”이 아니라 실제 서비스처럼 구성했습니다. 튜토리얼 버튼을 누르면 화면의 해당 영역이 빛나고, 왜 그 기술을 쓰는지 설명됩니다.

비밀값은
파일·GitHub·배포 서버에서
다르게 다룹니다

초보자가 가장 많이 헷갈리는 지점은 “내 컴퓨터의 `.env.local`이 배포 서버에도 자동으로 따라가는가?”입니다. 정답은 아닙니다. GitHub에는 올리지 않고, 배포 서비스에는 따로 입력합니다.

수업 핵심 브라우저에 공개되는 값과 서버에만 있어야 하는 값을 나눕니다. `PAYMENT_SECRET`, `ADMIN_TOKEN`, `DATABASE_URL`은 절대 화면 코드에 두지 않습니다.

배포 서버에는 직접 입력GitHub에는 비밀 파일을 올리지 않기 때문에, Vercel 같은 배포 서비스의 설정 화면에 운영 값을 다시 넣습니다.
src/firebase.ts
const env = process.env;

const firebaseConfig = {
  apiKey:
    env.NEXT_PUBLIC_FIREBASE_API_KEY,
  projectId:
    env.NEXT_PUBLIC_FIREBASE_PROJECT_ID,
};

initializeApp(firebaseConfig);
