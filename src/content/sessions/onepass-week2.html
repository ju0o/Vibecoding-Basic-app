WHY CLI

왜 CLI(터미널)에서 작업하나

채팅창
편하지만 — 대화가 흩어지고, 파일·기록·자동화와 분리됩니다.
CLI
작업 폴더 안에서 실행 → 변경·기록이 그대로 남고, 반복을 자동화·재현할 수 있습니다.

CLI는 "AI를 내 프로젝트 폴더 안으로 데려오는" 방식입니다 — 결과가 파일·기록으로 남습니다.

요청한 문장
→
실행파일 변경
→
확인diff·실행

자동으로 끝나지 않습니다 — 요청하고, 변경을 직접 확인하는 흐름을 반복합니다.

CONCEPT · MCP

MCP — AI에 외부 능력을 끼우는 콘센트

AI
Claude · Codex
파일 시스템
데이터베이스
브라우저
외부 API

AI 자체는 대화만 합니다. MCP를 꽂으면 파일·DB·브라우저 같은 실제 능력을 쓸 수 있습니다.

HOW · MCP

MCP 작동 — 요청이 외부 서버를 거쳐 돌아온다

AIClaude/Codex
파일 읽어줘 / DB 조회해줘
결과를 받아 사용
MCP 서버파일·DB·브라우저

AI가 직접 하는 게 아니라, MCP 서버에 요청해 결과를 받아 작업에 씁니다.

EXAMPLES · MCP

MCP로 연결하는 실제 능력들

파일 시스템
프로젝트 파일을 읽고 고침
데이터베이스
실제 데이터를 조회·정리
브라우저·API
화면 확인·외부 서비스 호출

필요한 능력만 골라 꽂습니다 — 모두 연결할 필요는 없습니다.

SAFETY · MCP

MCP 권한 — 최소 권한 + 승인으로 안전하게

"파일 전체 삭제" 요청
승인 필요
읽기만 허용 · 쓰기는 승인 후

많이 연결할수록 위험도 커집니다 — 필요한 만큼만, 민감한 작업은 승인을 거칩니다.

CONCEPT · SKILL

Skill — 반복 작업을 레시피로 저장

📋 SKILL · "PR 요약"
트리거: "PR 요약해줘"1. 변경된 파일 수집2. diff를 사람이 읽게 요약3. 리뷰 체크리스트 작성
한 번 정리 → 언제든 같은 품질로 재사용

매번 똑같이 설명하던 작업을 트리거·절차·예시가 든 자산으로 만들어 둡니다.

HOW · SKILL

Skill 작동 — 트리거 → 절차 → 재사용

트리거언제 쓰나
→
절차정해진 단계
→
검증통과 기준
→
재사용같은 결과

즉흥 지시 대신 정해진 절차를 부르므로, 누가·언제 해도 결과가 같습니다.

MCP vs SKILL

MCP는 능력 연결, Skill은 절차 저장

MCP
무엇을 할 수 있나 — 파일·DB·브라우저 같은 외부 능력을 AI에 연결
Skill
어떻게 하나 — 반복 작업의 절차를 저장해 재사용

둘은 보완 관계입니다 — MCP로 능력을 늘리고, Skill로 절차를 고정합니다.
