PROJECT RULES

AI에게 매번 말하지 않으려면 규칙 파일에 적어 둡니다

CLAUDE.md · 프로젝트 규칙
# 프로젝트 규칙
- 답변은 한국어로 한다
- 기존 코드 스타일을 따른다
- .env 파일은 절대 수정하지 않는다
- 수정 후 npm run check를 실행한다
이 파일이 하는 일
새 대화를 열 때마다 AI가 가장 먼저 읽는 우리 프로젝트의 업무 지침입니다.같은 지적을 두 번 이상 반복했다면, 그 지적을 규칙 파일로 옮길 시간입니다.

Claude Code는 CLAUDE.md, Codex는 AGENTS.md — 이름은 달라도 “먼저 읽는 지침”이라는 역할은 같습니다.

RULES IN ACTION

같은 요청도 규칙이 있으면 결과가 달라집니다

규칙 없이 “버튼 색 바꿔줘”

임의의 파란색을 고르고, 새 CSS 파일을 만들고, 영어 주석을 답니다.

매번 결과가 달라서 매번 다시 설명해야 합니다.

규칙과 함께 같은 요청

프로젝트 팔레트의 색을 쓰고, 기존 파일을 수정하고, 검증 명령까지 실행합니다.

누가 요청해도 같은 기준의 결과가 나옵니다.

규칙은 AI를 제한하는 장치가 아니라 우리 프로젝트의 상식을 이식하는 일입니다.

CONTEXT MEMORY

AI의 작업 기억은 책상 크기만큼만 유지됩니다

대화 하나로 하루 종일

책상 위에 서류가 계속 쌓여 처음의 지시를 잊기 시작합니다.

답이 흐려지고, 이미 정한 내용을 다시 묻습니다.

작업 단위로 새 대화

새 책상에 규칙 파일이 다시 깔리고 판단이 선명해집니다.

끝낼 때 요약을 남기면 다음 대화가 그 요약에서 시작합니다.

대화가 길어져 답이 흐려지는 것은 고장이 아니라 책상을 치울 신호입니다.

BRANCH

VERIFY ROUTINE

수정이 끝날 때마다 3분 검증 루틴을 반복합니다

  • Diff에서 바뀐 파일과 규모를 확인한다
  • 실행해서 바뀐 화면을 직접 눈으로 본다
  • 모바일 폭(375px)에서도 한 번 확인한다
  • 커밋으로 저장 지점을 남기고 다음 작업으로 간다

이 루틴이 몸에 붙으면 AI의 속도를 불안 없이 쓸 수 있습니다.

RECOVERY

잘못된 폴더·잘못된 명령은 멈추고 되돌아가는 것이 정답입니다

INCIDENT · wrong working directory

AI가 프로젝트 밖의 파일을 읽고 있습니다.
새 명령을 더 넣지 말고, 현재 경로와 열려 있는 폴더부터 다시 확인합니다.

pwd → cd 프로젝트 루트 → ls → 다시 계획

오류가 나면 더 강한 명령을 넣지 않습니다. 현재 위치와 변경 범위로 돌아갑니다.

UNDO

잘못됐을 때는 세 단계로 되돌립니다

terminal · undo
$ git status저장 안 된 변경 3개 파일$ git checkout -- .마지막 저장 지점으로 복귀$ git log --onelinec103 · c102 · c101 — 더 이전 지점도 선택 가능

되돌리는 법을 알고 있는 사람만 실험을 두려워하지 않게 됩니다.

비싸지는 습관

반복 지시를 매번 다시 타이핑합니다.

아끼는 습관

작업 단위로 새 대화 — 필요한 맥락만 다시 읽습니다.

반복 지시는 규칙 파일에 저장해 둡니다.

요금제와 한도는 자주 바뀌므로 수업 전 공식 문서 기준으로 확인하고, 습관은 이 두 가지면 충분합니다.

COMMON MISTAKES

처음 2주 동안 누구나 하는 실수 네 가지

위치 없이 시작홈 폴더에서 명령 실행
→ pwd부터
검증 생략“됐다니까 됐겠지”
→ 화면으로 확인
대화 하나로 전부기억 한계로 품질 저하
→ 작업 단위 분리
커밋 없이 진행되돌릴 지점이 없음
→ 작게 자주 저장

넷 다 도구의 문제가 아니라 운영 습관의 문제이고, 오늘 배운 루틴으로 전부 예방됩니다.
