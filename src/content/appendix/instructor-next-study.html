01 · COURSE BOUNDARY

두 반은 목표가 다릅니다

응용반은 프로젝트를 상품으로 만드는 과정이고, 심화반은 AI가 반복 업무를 수행하는 작업 시스템을 만드는 과정입니다.

PRODUCT & BUSINESS

응용·수익화반

고객 문제, MVP 범위, 가격과 결제, 출시와 피드백을 다룹니다.

  • 결과물: 실제로 소개하고 판매할 수 있는 작은 상품
  • 강사의 역할: 기능을 줄이고 고객의 사용 장면을 선명하게 만들기
AGENTIC WORKFLOW

AI 워크스페이스 심화반

MCP, Skill, Agent, SubAgent와 운영 규칙을 연결합니다.

  • 결과물: 반복 업무 한 사이클을 처리하는 개인 AI 작업실
  • 강사의 역할: 권한, 종료 조건, 검증과 실패 복구를 가르치기
02 · STUDY MAP

강사가 먼저 설명할 수 있어야 하는 개념

도구의 버튼 위치보다 개념의 경계와 실패 사례를 설명할 수 있어야 합니다.

PRODUCT

고객 문제와 가치

아이디어, 기능, 문제, 고객, 가치 제안의 차이를 실제 사용 장면으로 구분합니다.

  • 누가 지금 불편한가?
  • 현재 어떤 방식으로 해결하는가?
  • 왜 이 제품을 선택하는가?
MVP

최소 상품 범위

MVP는 못 만든 버전이 아니라 가장 중요한 가설을 확인하는 최소한의 완성된 흐름입니다.

  • 핵심 사용자 행동 1개
  • 필수 화면과 데이터
  • 이번 버전에서 하지 않을 것
REVENUE

가격과 결제 운영

가격표뿐 아니라 결제 전후 상태, 취소, 환불, 세금, 고객지원까지 하나의 운영 흐름으로 이해합니다.

MCP

연결 표준과 권한

host, client, server와 tools, resources, prompts의 차이를 이해합니다. 연결보다 권한 범위를 먼저 설계합니다.

SKILL

재사용 가능한 작업 규격

좋은 Skill은 긴 프롬프트가 아니라 사용 조건, 입력, 절차, 산출물, 검증과 실패 기준을 갖습니다.

AGENT

실행 루프와 종료 조건

Agent는 지침과 도구를 가지고 여러 단계를 실행합니다. 언제 멈추고 언제 사람에게 물을지를 정해야 합니다.

TEAMS

Manager와 Handoff

Manager는 전문 Agent를 도구처럼 호출해 결과를 종합하고, handoff는 전문 Agent에게 대화의 주도권을 넘깁니다.

WORKSPACE

규칙·메모리·도구 묶기

폴더 구조, 프로젝트 규칙, 문서, Skill, MCP, hooks와 작업 기록을 일관된 운영 방식으로 묶습니다.

OPERATIONS

관찰과 복구

작업 로그, 도구 호출, 변경 파일, 비용, 실패 지점을 확인하고 사람이 승인하거나 되돌릴 수 있어야 합니다.

03 · EXPLANATION DEPTH

수업에서 어디까지 설명할 것인가

입문자에게 구현 세부를 모두 보여주기보다, 선택과 검증에 필요한 깊이까지만 설명합니다.

주제반드시 설명심화로 남길 내용
수익화고객 문제, 핵심 사용 흐름, 가격 이유, 결제 전후 상태, 지원 범위세무·법률 판단, 복잡한 가격 최적화, 대규모 성장 실험
MCP연결 대상, 읽기·쓰기 권한, 입력과 출력, 실패 시 영향프로토콜 전송 계층, SDK 내부 구현, 자체 서버 배포
Skill언제 쓰는지, 필요한 입력, 작업 순서, 결과 형식, 검증 기준복잡한 런타임 플러그인과 배포 체계
Agent목표, 도구, 상태, 종료 조건, 사람 승인 지점대규모 평가 시스템과 분산 실행 인프라

워크스페이스프로젝트 규칙, 문서, 메모리, Skill, MCP와 기록의 위치모든 업무를 자동화하려는 과도한 시스템
04 · PRACTICE STANDARD

실습은 연결 성공이 아니라 검증까지

각 실습은 눈에 보이는 산출물과 실패 복구 장면을 포함해야 합니다.

응용 1강

한 고객의 한 문제를 실제 상황 문장으로 작성하고 인터뷰 질문 5개를 만듭니다.

검증: 기능명이 아니라 사용자의 현재 행동이 적혀 있는가?

응용 2강

핵심 흐름 하나를 선택해 필요한 화면·데이터·관리 기능과 제외 범위를 정합니다.

검증: 1주 안에 시연 가능한 범위인가?

응용 3강

무료, 일회성, 구독 중 하나를 선택해 결제 전후 화면과 지원 정책을 설계합니다.

검증: 결제 실패·취소·환불 상태가 있는가?

응용 4강

공개 URL, 소개 문구, 첫 사용자 피드백 수집과 다음 개선 3개를 준비합니다.

검증: 실제 사용자가 한 번 끝까지 사용할 수 있는가?

심화 1강

읽기 전용 MCP 하나를 연결하고 호출 가능한 도구와 접근 데이터를 표로 만듭니다.

검증: 쓰기 권한 없이도 목표를 달성하는가?

심화 2강

반복 업무 하나를 Skill로 만들고 잘못된 입력과 실패 조건을 시험합니다.

검증: 다른 사람이 같은 결과 형식을 얻는가?

심화 3강

단일 Agent가 계획·실행·검증·복구를 수행하도록 종료 조건을 설정합니다.

검증: 실패 시 무한 반복하지 않고 멈추는가?

심화 4강

리서치, 구현, QA 역할을 나누고 manager 또는 handoff 방식을 선택합니다.

검증: 같은 파일을 동시에 수정하지 않는가?

심화 5강

프로젝트 규칙, Skill, MCP, 메모리와 작업 기록을 개인 워크스페이스로 묶습니다.

검증: 새 대화에서도 동일한 작업 방식을 재현하는가?

심화 6강

반복 업무 한 사이클을 실행하고 도구 호출, 결과, 실패와 개선점을 발표합니다.

검증: 자동화하지 말아야 할 구간도 설명하는가?

05 · EXPECTED QUESTIONS

예상 질문과 답변 기준

제품마다 기능 이름이 달라질 수 있으므로, 특정 서비스보다 판단 원칙을 중심으로 답합니다.

MCP를 쓰면 API를 몰라도 되나요?

아닙니다. MCP는 연결 인터페이스를 표준화하지만 실제 데이터 구조, 권한, 실패 응답과 비용은 여전히 이해해야 합니다.

Skill은 프롬프트 저장 기능인가요?

프롬프트를 포함할 수 있지만 핵심은 사용 조건, 입력, 절차, 산출물과 검증 기준을 재사용 가능하게 묶는 것입니다.

Agent가 알아서 끝까지 하면 더 좋은가요?

항상 그렇지 않습니다. 비용이 크거나 되돌리기 어려운 작업에는 사람 승인 지점을 두고, 종료 조건을 명시해야 합니다.

Agent를 많이 만들수록 성능이 좋아지나요?

역할이 겹치면 맥락 전달과 충돌 비용이 커집니다. 단일 Agent로 시작하고 별도 전문 맥락이 필요한 경우에만 분리합니다.

수익화는 결제만 붙이면 되나요?

결제는 한 단계입니다. 고객 문제, 가격 이유, 결제 전후 경험, 환불과 지원, 재사용 이유까지 연결되어야 상품이 됩니다.

나만의 AI 워크스페이스는 자동화 프로그램인가요?

자동화만 의미하지 않습니다. 프로젝트 규칙과 지식, 재사용 절차, 연결 도구와 검증 기록을 일관된 작업 환경으로 묶는 것입니다.
