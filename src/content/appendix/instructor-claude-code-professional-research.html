01 · COURSE BOUNDARY

Claude Code Professional의 차별점

Claude Code 수업은 “AI가 코드를 고쳐준다”가 아니라, 터미널 기반 에이전트 루프를 안전하게 운영하는 능력을 가르칩니다.

구분Workflow ArchitectClaude Code Professional수업에서 지켜야 할 선
목표AI 업무 구조와 도구 선택 원리Claude Code의 세션, 권한, 지속 지침, 확장, 자동화, PR 흐름을 실제 저장소에서 운영이론은 10분 이내로 복습하고 바로 터미널·파일·로그·PR 장면으로 들어갑니다.
핵심 증거워크플로 도식과 판단표터미널 로그, CLAUDE.md, settings, Skill, Hook, MCP config, subagent 결과, PR전문과정에서는 텍스트 카드보다 실행 증거와 실패 복구 장면이 우선입니다.
Claude다운 지점도구 독립적인 설계gather context → take action → verify results 루프, permission modes, checkpoints, auto memory도구명보다 세션 운영, 컨텍스트 관리, 검증 루프를 보여줍니다.
주의개념이 깊어질수록 별도 과정화Agent Teams는 실험 기능이며 비용과 조율 부담이 큽니다.실험 기능은 “가능하다”보다 “언제 쓰면 안 되는가”까지 함께 가르칩니다.
강사용 기준: Claude Code 전문과정의 중심 질문은 “Claude가 무엇을 할 수 있나?”가 아니라 “Claude가 무엇을 보고, 무엇을 실행하고, 무엇으로 검증하며, 어디서 사람이 멈춰야 하는가?”입니다.
02 · OPERATING MODEL

Claude Code를 한 장으로 설명하는 지도

수강생에게 처음 보여줄 장면은 터미널 하나가 여러 운영 표면으로 확장되는 지도여야 합니다.

Terminal기본 작업실입니다. 프로젝트 루트에서 시작하고 명령, 파일, Git 상태를 함께 다룹니다.
CLAUDE.md매 세션에 로드되는 프로젝트·사용자·조직 지침입니다. 반복 설명을 여기에 둡니다.
Settings권한 모드, scope, hooks, plugins, MCP 같은 실행 환경을 관리합니다.
Skills반복 절차를 필요한 때만 불러오는 재사용 업무 단위입니다.
MCP외부 도구, DB, 이슈, 모니터링, 디자인 자료를 연결하는 통로입니다.
AgentsSubagent와 Agent Team으로 탐색, 리뷰, 병렬 작업을 분리합니다.
오해 차단: Claude Code는 “프롬프트 잘 쓰면 끝”이 아닙니다. 프로젝트 루트, permission mode, CLAUDE.md, settings scope, Skill trigger, MCP 인증, Hook 실패 정책을 구분해야 현장에서 안정적으로 운영됩니다.
03 · OFFICIAL STUDY ORDER

공식자료를 공부하는 순서

아래 순서로 읽으면 Claude Code를 기능 목록이 아니라 운영 체계로 이해할 수 있습니다. 원문 전체를 복사하지 말고, 강의에서는 쉬운 한국어와 실제 시연으로 바꿉니다.

1. Overview

Claude Code가 코드베이스를 읽고, 파일을 수정하고, 명령을 실행하며 개발 도구와 통합되는 agentic coding tool이라는 큰 역할을 잡습니다.
code.claude.com/docs/en/overview

2. How Claude Code works

수업의 핵심 루프입니다. context gathering, action, verification이 반복되며, 모델과 도구가 함께 agentic loop를 구성합니다.
code.claude.com/docs/en/how-claude-code-works

3. Quickstart + permission modes

설치 명령보다 중요한 것은 프로젝트 루트에서 시작하고, 읽기·쓰기·명령 실행의 승인 경계를 이해하는 것입니다.
code.claude.com/docs/en/quickstart
code.claude.com/docs/en/permission-modes

4. Memory and settings

CLAUDE.md, auto memory, rules, settings scope를 분리합니다. 강의에서는 “지침·학습·정책·개인설정”으로 번역합니다.
code.claude.com/docs/en/memory
code.claude.com/docs/en/settings

5. Skills and plugins

반복 절차는 Skill, 공유·배포·버전 관리는 Plugin입니다. Claude는 Skill body를 필요할 때 로드한다는 점을 강조합니다.
code.claude.com/docs/en/skills
code.claude.com/docs/en/plugins

6. MCP and hooks

MCP는 외부 시스템 연결이고 Hook은 lifecycle 이벤트에서 정책을 실행합니다. 둘 다 권한과 실패 정책이 핵심입니다.
code.claude.com/docs/en/mcp
code.claude.com/docs/en/hooks

7. Subagents and Agent Teams

Subagent는 한 세션 안의 위임, Agent Team은 여러 Claude Code 인스턴스의 팀 운영입니다. Agent Teams는 실험 기능이므로 제한을 함께 가르칩니다.
code.claude.com/docs/en/sub-agents
code.claude.com/docs/en/agent-teams

8. GitHub Actions

전문 과정의 마지막은 세션 결과를 PR과 CI/CD로 옮기는 것입니다. GitHub App, secrets, workflow, review 기준을 분리합니다.
code.claude.com/docs/en/github-actions

05 · SIX LESSONS

6회차별 전문 강의 설계

각 회차는 고유 장면, 정상 흐름, 실패 흐름, 복구 흐름, 강사용 심화 해설을 반드시 갖습니다.

01
FOUNDATION

설치·터미널·세션·권한·저장소 탐색

대표 장면: 잘못된 홈 폴더 세션과 올바른 프로젝트 루트 세션을 나란히 보여주고, plan mode에서 읽기 탐색 후 작은 diff로 이동합니다.

실습: 저장소 지도, 현재 permission mode, 첫 안전한 변경, 검증 명령을 한 장에 기록합니다.

02
PROJECT CONTROL

CLAUDE.md·계획·Git·Diff·테스트

대표 장면: 반복 설명이 CLAUDE.md와 path rule로 정리되고, diff와 test가 Git checkpoint로 고정되는 운영판.

실습: CLAUDE.md 초안, 검증 명령 2개, 금지 행동 2개, 테스트 포함 commit을 만듭니다.

03
REUSABLE WORK

Skills와 반복 작업 표준화

대표 장면: 붙여넣던 체크리스트가 SKILL.md, supporting files, trigger, verification으로 분리되는 Skill loader.

실습: 반복 업무 하나를 Skill로 만들고 정상 요청, 엉뚱한 요청, 실패 요청 3개로 테스트합니다.

04
EXTENSIONS

Plugins·MCP·Hooks와 서비스 연결

대표 장면: Skill, agent, hook, MCP, settings가 plugin root에서 묶이고, 쓰기 도구 앞에 Hook gate가 켜지는 확장 설계도.

실습: 개인 Skill을 Plugin 후보로 묶고, 읽기 전용 MCP 또는 모의 Tool, Hook 실패 정책을 작성합니다.

05
MULTI AGENT

Subagents·Agent Teams·리뷰 게이트

대표 장면: Explore/Plan subagent가 컨텍스트 오염을 줄이고, Agent Team은 lead, teammate, shared task list로 분리되는 관제판.

실습: 병렬 가치가 있는 작업만 골라 역할, 파일 소유권, 반환 형식, reviewer gate를 작성합니다.

06
OPERATIONS

자동화·배포·PR·Claude 워크스페이스

대표 장면: Claude 세션 결과가 branch, tests, PR, GitHub Action, deploy, handoff summary로 이동하는 릴리즈 파이프라인.

실습: 최종 Claude 워크스페이스 운영 매뉴얼과 PR 템플릿, CI 실패 복구 시나리오를 완성합니다.

06 · MOTION BRIEF

슬라이드와 애니메이션 고도화 기준

Claude Code 전문과정의 모션은 터미널·파일·권한·검증의 인과 관계를 보여줘야 합니다.

AGENTIC LOOP

세 단계 루프

Gather context, take action, verify results 세 노드를 원형으로 배치합니다. 테스트 실패 시 verify에서 gather로 되돌아가는 루프를 수동 진행합니다.

PERMISSION RAIL

권한 모드는 레일이다

default, acceptEdits, plan, auto, dontAsk, bypassPermissions를 레일로 보여주고, 위험도가 올라갈수록 감독·격리·복구 필요성이 같이 켜집니다.

MEMORY STACK

CLAUDE.md와 memory 구분

사용자 작성 지침과 Claude가 저장한 auto memory를 두 층으로 보여줍니다. 보안 정책은 Hook으로 빠지는 분기선을 함께 표시합니다.

PLUGIN BUNDLE

확장은 묶음이다

skills, agents, hooks, .mcp.json, settings.json이 plugin root에 모이고, .claude-plugin/plugin.json은 식별표 역할만 하도록 강조합니다.

TEAM BOARD

팀은 역할 경계다

Lead, teammate, shared task list, mailbox를 실제 보드처럼 배치합니다. 같은 파일을 잡으면 충돌 표시, 독립 작업이면 병렬 진행으로 보여줍니다.

PR PIPELINE

작업은 PR로 검증된다

issue, branch, diff, test, PR comment, GitHub Action, review, deploy가 순서대로 켜지고 실패 시 해당 노드에서 멈춥니다.

07 · SCRIPT TEMPLATE

강사용 대본을 얕게 만들지 않는 틀

Claude Code 수업은 “이 버튼을 누르세요”가 아니라 세션 운영 판단을 가르쳐야 합니다.

SAY / DO / ASK

수업 중 실제 멘트 구조

SAY

“Claude Code가 강한 이유는 한 번에 정답을 말해서가 아니라, 프로젝트를 읽고, 행동하고, 검증하면서 방향을 조정하는 루프를 갖기 때문입니다.”

DO

터미널에서 계획 단계, 파일 읽기, 작은 diff, 테스트 실행, 실패 후 재시도를 한 단계씩 멈춰 보여줍니다.

ASK

“지금 단계에서 Claude가 새로 알게 된 정보는 무엇이고, 다음 행동은 왜 달라져야 할까요?”

DEEP / RECOVER

전문 과정의 깊이를 만드는 부분

근거

공식 문서의 agentic loop, permission modes, checkpoints, CLAUDE.md와 auto memory 구분을 실제 화면과 연결합니다.

복구

권한 모드가 너무 느슨하거나, CLAUDE.md가 과밀하거나, MCP 인증이 빠지거나, 팀 작업이 충돌하는 상황을 준비합니다.

시간

시간이 부족하면 확장 기능 설명을 줄이고 “루트 확인 → plan → diff → test → PR note” 흐름만 남깁니다.

09 · PROFESSIONAL Q&A

강사가 준비해야 할 질문

질문에 답할 때는 기능명보다 세션 운영 기준, 권한, 검증 증거를 먼저 말합니다.

Q1

Claude Code와 Codex는 어떻게 다르게 가르치나요?

Claude Code는 터미널 세션, CLAUDE.md, permission modes, checkpoints, Skill/Plugin/MCP/Hook, Agent Teams 흐름을 중심으로 갑니다. Codex는 App/CLI/IDE/Browser/Review/Release를 포함한 표면 선택과 검증 운영을 더 강조합니다.

Q2

CLAUDE.md와 Skill은 무엇이 다른가요?

CLAUDE.md는 매 세션에 유지될 사실과 규칙이고, Skill은 특정 업무를 수행하는 절차입니다. “항상 알아야 할 것”은 CLAUDE.md, “반복해서 수행할 것”은 Skill로 분리합니다.

Q3

Auto memory를 믿어도 되나요?

Auto memory는 Claude가 배운 패턴을 저장하는 보조 장치입니다. 보안 금지, 승인 정책, 팀 규칙처럼 강제해야 하는 것은 CLAUDE.md, settings, hooks로 분리해야 합니다.

Q4

Agent Teams는 언제 별도 과정으로 빼야 하나요?

역할 설계, task dependency, teammate communication, hooks quality gate, 비용·토큰, cleanup까지 다루기 시작하면 Claude Code Professional 안의 한 회차로는 부족합니다. 그때는 Agent Systems 또는 Team Automation 과정으로 분리하는 편이 좋습니다.

Q5

Hooks는 왜 위험할 수 있나요?

Hook은 자동으로 실행됩니다. 잘못 설정하면 정상 작업을 막거나 민감 정보를 잘못 처리할 수 있습니다. 따라서 event, matcher, exit code, 실패 정책을 먼저 설계해야 합니다.

Q6

GitHub Actions는 그냥 자동 PR인가요?

아닙니다. Claude Code 작업이 팀 저장소의 review, secrets, CI, permissions, PR 기록으로 들어가는 운영 단계입니다. 강의에서는 “자동화”보다 “검증 가능한 협업 기록”으로 설명합니다.
