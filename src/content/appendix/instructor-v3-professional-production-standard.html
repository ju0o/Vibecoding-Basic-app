01 · PRODUCTION PIPELINE

각 회차 제작 순서

슬라이드를 먼저 만들지 않습니다. 공식자료와 실제 시연 기준을 먼저 잡은 뒤 화면과 대본을 만듭니다.

1. 공식자료출처 URL, 확인 날짜, 안정성, 핵심 개념, 오해를 정리합니다.
2. 대표 장면그 회차에서 기억에 남을 실제 작업실 화면을 한 장면으로 정합니다.
3. 대본SAY / DO / ASK / 예상 답변 / 심화 설명 / 복구를 작성합니다.
4. 시연정상 흐름과 실패 흐름을 실제 도구 또는 시뮬레이션으로 준비합니다.
5. 실습수강생이 40분 안에 확인 가능한 산출물을 만들게 합니다.
6. QA프로젝터, 오프라인, 인쇄, 1280×720 화면에서 검수합니다.
강의 품질 기준: 공식자료 링크만 있는 자료, 추상 카드만 있는 슬라이드, 실패 복구가 없는 실습, 강사가 읽을 상세 대본이 없는 회차는 V3 ready로 보지 않습니다.

외부 시스템과 AI 앱을 연결하는 표준으로 소개합니다. 수업에서는 USB-C 비유를 쓰되, “연결되면 무엇을 읽고 쓸 수 있는가”까지 이어갑니다.

원격 서버 신뢰, 최소 권한, 인증 검증, 세션·토큰 위험을 강사가 먼저 이해합니다. 수강생에게는 “처음 연결은 읽기 전용부터”로 설명합니다.

04 · WHAT TO BUILD NEXT

다음 고도화 작업 우선순위

새 과정을 늘리기보다 현재 과정의 회차별 밀도를 먼저 올립니다.

1순위

Workflow Architect 4회차 재제작

Agent/MCP/Skill의 경계가 모든 전문과정의 기반입니다. 로그 분석실, 컨텍스트 설계판, MCP 권한망, Agent 관제실을 실제 작업 화면처럼 만듭니다.

2순위

Claude/Codex 각 1강 실제 도구 화면화

카드형 설명이 아니라 터미널 세션, 권한 승인, 파일 diff, 검증 로그가 한 화면에서 보이게 재구성합니다.

3순위

공식자료 학습실을 회차별 study path로 재구성

링크 목록이 아니라 “먼저 읽을 것, 수업에서 말할 것, 오해, 시연 포인트, 예상 질문”이 회차별로 보여야 합니다.

4순위

실습 예제 프로젝트 품질 강화

starter/broken/complete가 실제 실행 가능하고, 실패 로그와 정답 diff가 회차별 실습 목표와 정확히 맞아야 합니다.
