Claude Code를 가르치기 전에

T01
학습 기준: Claude Code를 단순 채팅창이 아니라 코드베이스를 읽고 파일을 수정하고 명령을 실행하는 agentic coding tool로 설명합니다.

작업 표면

공식 문서상 터미널, VS Code, JetBrains, 데스크톱과 웹에서 사용할 수 있습니다. 수업에서는 하나의 표면을 기준으로 진행하고 다른 표면의 버튼 위치가 같다고 단정하지 않습니다.

작업 루프

코드베이스 탐색 → 계획 → 여러 파일 수정 → 명령 실행 → diff와 테스트 확인 → Git 작업으로 이어집니다.

CLAUDE.md

세션 시작 시 읽는 지속 지침입니다. build 명령, 구조, 코딩 규칙과 검토 기준을 짧고 구체적으로 기록합니다.

Auto memory

Claude가 교정과 작업에서 발견한 학습을 저장하는 별도 기억입니다. CLAUDE.md는 사람이 작성한 규칙, auto memory는 Claude가 쓴 학습이라는 차이가 있습니다.

MCP

외부 데이터와 도구를 연결합니다. 연결 자체보다 어떤 도구와 데이터를 어떤 권한으로 노출하는지 확인합니다.

Subagents / Agent teams

전문 역할을 별도 컨텍스트와 권한으로 실행하거나 여러 Agent가 작업을 나눕니다. 파일 소유권과 결과 형식을 먼저 정합니다.

Windows 설치 설명

공식 설치 방식은 변경될 수 있으므로 수업 직전 Claude Code 공식 Overview의 Windows 항목을 확인합니다.
현재 공식 문서에는 PowerShell 설치 스크립트와 WinGet 설치가 안내되어 있습니다.
PowerShell과 CMD의 명령 문법을 섞지 않습니다. 프롬프트가 `PS C:\`인지 먼저 확인합니다.
네이티브 Windows에서 Bash 도구를 사용할 경우 Git for Windows가 권장될 수 있습니다. WSL은 별도 환경입니다.

CLAUDE.md를 잘 쓰는 기준

넣을 것

실행·테스트 명령, 중요한 폴더, 검증 가능한 코딩 규칙, 금지 사항, 완료 기준.

빼거나 분리할 것

한 번만 필요한 요청, 긴 업무 절차, 특정 경로에만 필요한 규칙, 서로 충돌하는 오래된 지침.

범위

프로젝트 루트 CLAUDE.md는 팀 공통, 사용자 홈은 개인 공통, CLAUDE.local.md는 git에 올리지 않을 개인 프로젝트 설정입니다.

AGENTS.md와 함께 쓰기

Claude Code는 CLAUDE.md를 중심으로 읽습니다. 공통 규칙이 AGENTS.md에 있다면 CLAUDE.md에서 `@AGENTS.md`로 가져오는 구성을 검토합니다.

예상 질문

Q. Claude.ai 채팅과 Claude Code는 같은가요?

같은 Claude 계열을 사용하지만 Claude Code는 프로젝트 파일과 명령 실행 도구를 사용하는 코딩 작업 환경입니다.

Q. CLAUDE.md에 모든 문서를 넣으면 더 좋은가요?

아닙니다. 시작 컨텍스트를 소비하므로 항상 필요한 짧고 구체적인 규칙만 두고 절차는 Skill이나 경로별 rules로 분리합니다.

Q. 권한을 모두 허용하면 더 빠른가요?

빠를 수 있지만 잘못된 쓰기와 명령 위험이 커집니다. 신뢰한 저장소에서도 위험한 행동은 승인과 검토를 남깁니다.

Q. 여러 Agent가 항상 더 좋은가요?

아닙니다. 독립적으로 나눌 수 있는 큰 작업에 유리하고, 같은 파일을 동시에 수정하면 조정 비용과 충돌이 증가합니다.

공식 확인 위치: Claude Code Docs의 Overview, How Claude remembers your project, MCP, Subagents, Permission modes. 제품 기능과 설치 명령은 수업 직전에 다시 확인합니다.
