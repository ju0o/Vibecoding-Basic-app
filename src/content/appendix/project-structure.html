프로젝트 폴더 구조 설명

AI가 만든 프로젝트를 처음 열면 파일이 너무 많아 보입니다. 하지만 자주 보는 파일은 몇 개뿐입니다.

1

웹 프로젝트 기본 구조

my-app/ src/ app/ components/ lib/ public/ node_modules/ package.json package-lock.json README.md .gitignore .env .env.local .env.example
package.json
프로젝트 정보, 실행 명령어, 설치된 패키지 목록이 들어있습니다.
src/
source의 줄임말로, 실제 화면과 기능 코드가 들어있는 핵심 작업 폴더입니다. 대부분의 수정은 여기에서 일어납니다.
public/
이미지, 아이콘, 정적 파일을 넣는 폴더입니다. src 안이 아니라 프로젝트 루트에서 src와 같은 선상에 있는 경우가 많습니다.
node_modules/
npm install로 받은 외부 패키지가 모이는 자동 생성 폴더입니다. src 안에 넣거나 직접 수정하지 않습니다.
.env.local
내 컴퓨터에서만 쓰는 실제 비밀값 파일입니다. GitHub에 올리면 안 됩니다.
.env.example
필요한 환경변수 이름만 공유하는 견본 파일입니다. 실제 API 키나 비밀번호는 넣지 않습니다.
.gitignore
GitHub에 올리지 않을 파일과 폴더를 지정합니다.
2

초보자가 자주 만지는 파일

README.md
프로젝트 설명서입니다. 실행 방법과 작업 요약을 정리합니다.
components/
버튼, 카드, 헤더처럼 재사용되는 UI 조각이 들어갑니다.
app/ 또는 pages/
페이지 단위 코드가 들어갑니다. 화면을 바꾸고 싶을 때 자주 봅니다.
lib/
API 연결, DB 연결, 공통 함수가 들어가는 경우가 많습니다.
styles/
색상, 폰트, 간격, 반응형 화면처럼 시각 규칙을 관리합니다. 프로젝트에 따라 파일이 각 컴포넌트 옆에 있을 수도 있습니다.
package-lock.json
설치된 패키지의 정확한 버전을 자동 기록합니다. 직접 작성하거나 편집하는 파일이 아닙니다.
3

자주 만나는 파일 형식

.js / .jsx
JavaScript 코드와 화면 코드를 담습니다. JSX는 화면 구조를 함께 표현할 수 있습니다.
.ts / .tsx
TypeScript 코드입니다. TSX는 화면 코드에 타입 검사까지 더한 형식입니다.
.css / .scss
색, 크기, 간격, 배치와 같은 화면 스타일을 정의합니다.
.json
프로젝트 설정과 구조화된 데이터를 기록합니다. 쉼표와 따옴표 규칙이 중요합니다.
.md
Markdown 문서입니다. README, 작업 계획, AI 작업 요약을 사람이 읽기 좋게 정리합니다.
4

바이브코딩 수정 순서

1. 화면
브라우저에서 바꾸고 싶은 장면과 결과를 한 문장으로 정합니다.
2. 검색
보이는 문구나 기능 이름으로 IDE 전체 검색을 실행합니다.
3. 설명
AI에게 관련 페이지, 컴포넌트, 스타일 파일의 연결 관계를 먼저 설명하게 합니다.
4. 수정
필요한 파일만 최소 범위로 수정하고 변경 파일 목록을 확인합니다.
5. 검증
브라우저에서 클릭, 모바일 화면, 다른 페이지의 영향까지 확인합니다.
5

파일별 수정 기준

자주 확인: src, components, public · AI와 영향 확인: package.json, 환경변수, 설정 파일 · 직접 수정하지 않기: node_modules, package-lock.json, build/dist 결과물. .env.local의 실제 값은 절대 공유하지 않습니다.
