2. GitHub에 변경 저장하기

git status

어떤 파일이 바뀌었는지 먼저 확인합니다.

git add .

이번 commit에 포함할 변경을 준비합니다.

git commit -m "메시지"

무엇을 바꿨는지 설명과 함께 저장합니다.

git push

저장한 commit을 GitHub로 전송합니다.

AI IDE가 명령을 대신 입력해도 마지막 출력의 repository, branch, error 여부는 직접 확인합니다.

Vercel

GitHub 저장소를 연결해 웹 프로젝트를 빠르게 배포하고 Preview URL을 확인하기 좋습니다.

Firebase Hosting

Google 프로젝트와 연결하고 Hosting, 로그인, 데이터 기능을 함께 사용할 때 편리합니다.

3. 공개하면 안 되는 값

결제 비밀키, AI API 키, 관리자 DB 주소, 서비스 계정 파일을 코드에 직접 쓰지 않습니다.
실제 값이 들어간 `.env`, `.env.local`, `.env.*.local`이 `.gitignore`에 포함되어 있는지 확인합니다.
공유가 필요할 때는 실제 값이 없는 `.env.example`에 변수 이름만 적습니다.
배포 서비스의 Environment Variables에 실제 값을 별도로 입력합니다.
`NEXT_PUBLIC_`, `VITE_`처럼 브라우저에 전달되는 변수에는 비밀값을 넣지 않습니다.
이미 노출된 비밀키는 삭제만 하지 말고 폐기한 뒤 새로 발급합니다.

4. 배포 전 4단계 점검

`npm run build`가 오류 없이 끝납니다.
GitHub의 변경 파일과 commit 기록에 비밀값이 없습니다.
공개 URL에서 로그인·저장·주요 버튼을 다시 눌렀습니다.
다른 브라우저 또는 모바일 화면에서도 확인했습니다.
