INSTRUCTOR STUDY · SESSION 04

4강 파일 구조 이해 : 강사용 백그라운드 지식 가이드

S4 강사용 심화
강사 가이드의 철학:
초보 수강생들은 코드를 한 줄 고치기 위해 수천 줄의 파일을 마주했을 때 큰 인지 부담을 느낍니다. 4강의 목적은 폴더 이름을 암기시키는 것이 아닙니다. "내가 고쳐야 할 요소가 어느 역할의 파일에 있을지 추론하는 감각"을 길러주고, AI가 예상 밖의 파일을 수정해 생기는 오류를 사전에 줄이도록 가르치는 것입니다.

1. 대형 식당 주방 비유 (Kitchen Analogy) 교수법

수강생들이 Next.js나 React의 복잡한 디렉토리 트리를 처음 볼 때, '대형 레스토랑 주방'에 빗대어 설명하면 복잡도가 단번에 해소됩니다. 아래의 비유 관계를 수업 중에 상세하게 전달해 주세요.

주방 구역 프로젝트 폴더 수강생 눈높이 해설
저온 보관 구역 node_modules/ 외부 공급업체에서 납품받은 대용량 완제품(밀키트, 가공육 등) 보관소입니다. 주방 요리사들이 요리할 때 필요한 재료를 꺼내 쓰기만 할 뿐, 냉동고의 내용물을 포장지를 뜯어 직접 개조(수정)하지 않습니다.
전처리 구역 components/ 주문이 들어오면 바로 그릇에 올릴 수 있게 미리 슬라이스해 둔 파, 만들어 둔 특제 가니시, 기본 소스 그릇들입니다. 어떤 요리(Page)에든 바로 가져가서 얹어낼 수 있는 조립용 독립형 부품입니다.
조리 운영 구역 lib/ · utils/ 맛을 내는 황금 비율 소스 배합표, 고기 해동 시간 계산기처럼 뒤에서 작동하는 논리적 공식 문서입니다. 손님에게 이 레시피북 자체를 서빙하지는 않지만, 요리를 조리하기 위해 없어서는 안 될 계산 규칙입니다.
서비스 패스 app/ · pages/ 손님이 앉은 테이블 주소(URL)에 맞추어 주방 요리사들이 각 조리 준비대(components)의 재료들을 취합하여 손님에게 낼 최종 접시를 내어놓는 장소입니다. 사용자가 마주하는 최종 페이지입니다.

2. 강사가 정확히 구분해야 할 네 가지 파일 영역

Source code

src/, app/, pages/, components/처럼 사람이 작성하고 AI가 주로 수정하는 코드 영역입니다. 프로젝트에 src/가 없을 수도 있으므로 폴더 이름보다 역할을 먼저 봅니다.

Static assets

public/ 또는 src/assets/에 있는 이미지, 아이콘, 글꼴입니다. 프레임워크에 따라 브라우저에서 사용하는 주소 표기가 달라질 수 있습니다.

Project configuration

package.json, vite.config.*, next.config.*, tsconfig.json처럼 실행과 빌드 규칙을 정합니다. 수정 전 영향 범위를 AI에게 설명하게 합니다.

Generated or installed files

node_modules/, dist/, build/은 설치나 빌드 과정에서 만들어집니다. 직접 편집하지 않고 원본 코드나 설정을 고친 뒤 다시 생성합니다.

3. 파일과 경로 핵심 원리 판서 요령

추상적인 파일 개념과 경로 규칙을 학생들이 시각적으로 쉽게 이해할 수 있도록 돕는 칠판 판서 시각화 모델과 스피치 팁입니다.

✏️ 경로 시스템 판서 모델

[칠판 분필 드로잉 추천]
- 중앙에 아파트 건물 2개를 그립니다 (A동, B동).
- 절대경로(X): "서울시 강남구 A동 302호"라고 적은 종이 비행기를 날리면 바로 옆방에 전달되지 않는 문제를 시각화합니다.
- 상대경로(O): A동 302호 기준 ./301호 (옆방), ../B동/101호 (아래로 내려가서 옆동으로 이동)를 화살표 동선으로 연결합니다.
- 스피치 팁: "여러분, 절대경로는 내 방 주소를 행정구역 전체 주소로 외치는 것과 같아요. 우리가 프로젝트를 통째로 이사(배포)하면 행정구역이 바뀌기 때문에 작동이 멈춥니다. 반드시 ../와 ./라는 이웃집 경로로 대화해야 합니다."

✏️ 확장자 & index.html 판서

[확장자 번역사 비유]
- 동일한 모양의 텍스트 상자 세 개를 그립니다.
- 각각 .html, .css, .ts 이정표를 얹어놓고, 브라우저가 각기 다른 안경(해석기)을 끼고 이 텍스트들을 그림, 색상, 동작으로 변환하는 과정을 표현합니다.
- index.html의 대문 약속: 큰 레스토랑의 회전문(도메인 주소)을 통과하자마자 가장 먼저 고객을 맞이하는 '리셉션 데스크(웰컴 카드)'로 비유하여 설명합니다. "서버에게 세부 방 번호를 지정해주지 않으면, 무조건 index(웰컴 안내서)를 꺼내오는 것이 글로벌 규칙입니다."

4. AI가 기능을 여러 파일로 나눌 때의 코칭 요령

수강생의 프로젝트 주제와 관계없이, 화면 부품과 데이터 처리 로직을 연결할 때 자주 발생하는 오류와 강사의 대응 기준입니다.

예상 발생 오류 오류 발생 원인 (강사용 지식) 현장 코칭 처방전 (프롬프트 지시)
❌ Circular Dependency
(순환 참조 에러)		 page.tsx가 lib/api.ts를 가져오고, 다시 api.ts가 화면 컴포넌트를 가져오는 식으로 서로 import가 꼬일 때 발생. “데이터 처리 파일에서는 화면 UI나 React Hook을 가져오지 말고, 입력값을 받아 결과값을 돌려주는 역할로 분리해줘”라고 요청합니다.
❌ TypeError: undefined is not a function
(데이터 포맷 에러)		 데이터가 비어 있거나 예상한 형식과 다른 상태로 카드 컴포넌트에 전달되어 화면 렌더링이 중단될 때 발생. “데이터가 없을 때 보여줄 빈 상태와, 배열인지 확인하는 방어 코드를 먼저 넣어줘”라고 요청합니다.
❌ Next.js 클라이언트 컴포넌트 에러
(Server/Client boundary)		 Next.js에서 클릭, 상태, 브라우저 API가 필요한 컴포넌트를 서버 컴포넌트로 작성했을 때 발생. 무조건 선언문부터 추가하지 말고, 상호작용이 필요한 작은 컴포넌트만 클라이언트 컴포넌트로 분리할 수 있는지 AI에게 먼저 검토시킵니다.

5. 프로젝트 프레임워크별 폴더 대조표

Next.js(App Router vs Pages Router), React(Vite) 등 수강생의 프로그램 환경에 따라 폴더 이름과 구조가 미세하게 다릅니다. 당황하지 않고 아래 지도를 참고하여 안내해 주세요.

프레임워크 주소 페이지 위치 (app) 부품 위치 (components) 스타일 설정 (CSS) 정적 자원 (Assets)
Next.js (App Router) src/app/page.tsx src/components/ src/app/globals.css public/
Next.js (Pages Router) src/pages/index.tsx src/components/ src/styles/globals.css public/
Vite React App src/App.jsx (단일 페이지 위주) src/components/ src/index.css public/ 또는 src/assets/

6. 강사가 알아야 할 AI IDE 통제 노하우 (diff 검토)

AI는 가끔 과잉 구현을 하거나, 수강생이 요구하지도 않은 3D 그래픽 라이브러리 등을 설치하여 오류를 냅니다. 수강생이 코드 diff를 볼 때 아래 3가지 필터를 적용하도록 코칭해 주세요.

📌 확인 1: 변경된 파일 목록의 개수가 합당한가?

버튼 하나 바꿨는데 7개 파일이 수정되었다면 즉시 AI 작업을 멈추고 되돌리기(Rollback)를 시키거나, 어떤 파일들을 왜 건드렸는지 이유를 캐물어야 합니다.

📌 확인 2: package.json에 라이브러리가 추가되었는가?

수강생이 설치해 달라고 하지 않은 패키지가 AI 임의로 추가되었다면 "새로운 패키지 설치 없이 기존 리액트/스타일 문법으로만 다시 구현해 줘"라고 제약을 명시해야 불필요한 충돌을 막습니다.

📌 확인 3: 무의미한 대량의 빨간 줄(삭제)이 존재하는가?

AI가 리팩토링이라는 명목으로 수강생이 이전에 짜둔 핵심 컴포넌트를 통째로 유실시키는 경우가 발생합니다. 대폭 삭제가 일어났을 때는 브라우저를 켜기 전에 코드를 신중하게 롤백해야 합니다.

7. 강사 실전 코칭 행동 강령

10분: 실습 선정

수강생이 화면을 켜고 '바꾸고 싶은 컴포넌트 하나'를 정확히 고르게 유도합니다.

20분: 탐색 우선

바로 수정하지 않고, 수강생이 AI에게 관련 파일의 설명과 관계도부터 묻게 합니다.

30분: diff 브리핑

AI가 수정 완료하면, 수강생에게 "어떤 파일이 왜 바뀌었는지" 입으로 설명하게 해 보세요.

40분: 다중 검증

수정 후 PC 화면만 보지 말고, 개발자 모드를 켜서 모바일 반응형과 다른 페이지 연쇄 영향도 확인시키세요.

8. 수강생 예상 질문과 답변

프로젝트마다 구조가 조금씩 달라 생기는 질문에는 폴더명을 외우게 하기보다 역할과 확인 순서를 중심으로 답합니다.

Q. 제 프로젝트에는 src 폴더가 없는데 잘못 만든 건가요?

아닙니다. 프레임워크와 생성 옵션에 따라 app/, pages/, components/가 프로젝트 루트에 바로 있을 수 있습니다. package.json이 있는 프로젝트 루트를 기준으로 페이지와 부품 폴더의 역할을 찾으면 됩니다.

Q. node_modules 폴더는 정말 삭제하면 안 되나요?

직접 내부 파일을 수정하지 않는다는 뜻입니다. 설치가 꼬였을 때는 원인을 확인한 뒤 node_modules를 지우고 npm install로 다시 만드는 해결법도 있습니다. 초보자가 임의로 실행하지 않도록 AI에게 이유와 명령을 확인하게 합니다.

Q. package.json과 package-lock.json은 무엇이 다른가요?

package.json은 필요한 패키지의 범위와 실행 명령을 적는 프로젝트 설명서이고, package-lock.json은 실제 설치된 정확한 버전을 기록한 잠금 문서입니다. 둘 다 버전 관리에 포함하지만 lock 파일은 보통 설치 도구가 갱신합니다.

Q. 버튼 하나를 바꾸는데 AI가 파일을 여덟 개 수정했습니다.

바로 결과를 수락하지 말고 각 파일을 왜 바꿨는지 목록으로 설명하게 합니다. 요청과 관계없는 설정, 패키지, 공용 컴포넌트 변경이 있다면 되돌린 뒤 “새 패키지 없이 필요한 파일만 최소 수정”하도록 다시 요청합니다.

바이브코딩의 목표는 '문법을 아는 코더'가 아니라 'AI를 올바른 경로로 이끌고 검증하는 아키텍트'를 양성하는 것입니다.
