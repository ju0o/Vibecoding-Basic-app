1. 프로젝트 파일 구조를 주방 동선으로 이해하기

루트 기준: src/, public/, node_modules/, package.json, package-lock.json, README.md, .env* 파일은 모두 my-dashboard/ 바로 아래 같은 선상에 있습니다. public/이나 node_modules/를 src/ 안에서 찾지 않습니다.
my-dashboard/ ├─ src/ │ ├─ app/ │ │ ├─ layout.tsx │ │ └─ page.tsx │ ├─ components/ │ │ └─ Button.tsx │ ├─ lib/ │ │ └─ utils.ts │ └─ styles/ ├─ public/ │ └─ logo.png ├─ node_modules/ ├─ package.json ├─ package-lock.json ├─ README.md ├─ .gitignore ├─ .env ├─ .env.local └─ .env.example
폴더/파일명 수강생 필독 역할 요약
node_modules/ 설치된 외부 패키지의 실제 파일이 모이는 곳. 직접 편집하지 않으며, 문제가 생기면 설치 명령으로 다시 만듭니다.
src/app/ 주소창의 경로(URL)와 1:1로 매핑되는 서빙대. 예: /revenue 주소는 app/revenue/page.tsx가 담당.
src/components/ 재사용 가능한 조각 부품(버튼, 테이블, 카드 등). 여러 화면에 동시 사용되어 수정 시 영향 범위 전역적.
src/lib/ 데이터 요청, 값 변환, 계산처럼 여러 화면이 함께 쓰는 처리 도구를 모아둔 곳.
public/ src/ 안이 아니라 프로젝트 루트에 있는 정적 파일 폴더입니다. 도메인 주소 바로 뒤에 붙여서 꺼내 쓸 수 있는 이미지, 아이콘을 둡니다.
.env 프로젝트 환경값 파일입니다. 팀 정책에 따라 공통 기본값을 둘 수 있지만 실제 비밀값은 넣지 않는 쪽이 안전합니다.
.env.local 내 컴퓨터에서만 쓰는 실제 비밀값 파일입니다. src/ 안이 아니라 프로젝트 루트에 두고 GitHub에 올리지 않습니다.
.env.example 팀원과 AI에게 필요한 변수 이름만 알려주는 공유용 견본입니다. 실제 비밀값은 넣지 않습니다.

2. 초보자가 헷갈리는 파일 시스템 핵심 지식 3대장

① 확장자의 숨겨진 실체 .html / .css / .ts

소스 코드 파일은 사람이 읽을 수 있는 텍스트로 저장됩니다. 확장자는 브라우저와 개발 도구에 "이 파일을 HTML 구조, CSS 디자인 규칙, TypeScript 코드 중 무엇으로 해석할지" 알려주는 표지입니다. 이름만 바꾼다고 파일의 문법이 자동으로 변환되지는 않습니다.

② 웹 서버의 홈페이지 첫 대문 약속 index.html

정적 웹 서버는 주소 뒤에 파일명이 없을 때 해당 폴더의 index.html을 기본 문서로 찾는 경우가 많습니다. Next.js처럼 프레임워크를 사용하는 프로젝트에서는 app/page.tsx 또는 pages/index.tsx가 첫 화면 역할을 합니다. 프로젝트 종류에 따라 이름이 다를 수 있습니다.

③ 절대 경로(Absolute) vs 상대 경로(Relative)의 차이점과 배포 참사 방지

- 절대 경로: "내 컴퓨터 기준"의 고유 물리 주소입니다. (예: C:/MyWorkspace/project/src/logo.png). 로컬 컴퓨터에서는 이미지가 잘 보이지만, 프로젝트를 깃허브에 올리고 클라우드 서버에 배포하는 순간 서버 컴퓨터에는 그 주소가 없으므로 404 경로 에러(엑스박스)가 나게 됩니다.
- 상대 경로: "지금 내가 코딩하고 있는 파일"을 기준으로 이웃집을 찾는 방식입니다. (예: ./Button = 같은 층의 버튼, ../components/Card = 한 층 올라가서 컴포넌트 폴더의 카드). 이 방식을 쓰면 프로젝트를 어디로 복사해가든 에러 없이 견고하게 작동합니다.

■ 내 PC에만 있는 경로: C:/Users/user/Desktop/my-app/src/logo.png ■ 프로젝트 안에서 찾는 경로: ../../assets/logo.png 또는 프로젝트 별칭 @/assets/logo.png

3. 파일명 작명의 법칙 (대소문자 및 공백 금지 수칙)

공백은 피하기: 파일명에 공백을 사용할 수는 있지만 URL 인코딩과 도구 호환 때문에 관리가 번거로워집니다. 공백 대신 하이픈(-) 또는 언더바(_)를 사용하는 편이 안전합니다.
대소문자 정확히 맞추기: 개발 PC에서는 logo.png와 Logo.png의 차이가 드러나지 않을 수 있지만, 배포 서버에서는 서로 다른 파일로 취급될 수 있습니다. 실제 파일명과 import 문장의 대소문자를 항상 같게 적습니다.

1. 상대 경로 탐색 연습 문제 (빈칸 채우기)

Q1. 내가 현재 src/lib/formatPrice.ts 파일을 열고 있습니다. 같은 폴더에 있는 formatDate.ts 파일을 불러올 때 올바른 경로는 무엇일까요?
import { formatDate } from " ";
▶ Q1 정답 확인 및 해설
정답: ./formatDate
해설: 같은 폴더에 있는 파일을 가져올 때는 현재 위치를 뜻하는 점 한 개와 슬래시(./)로 시작합니다. TypeScript 확장자는 보통 생략할 수 있습니다.
Q2. 내가 현재 src/app/revenue/page.tsx에서 코딩 중입니다. 부모 폴더를 지나 src/components/Button.tsx 파일을 불러오려고 합니다. 올바른 경로는 무엇일까요?
import Button from " ";
▶ Q2 정답 확인 및 해설
정답: ../../components/Button
해설: app/revenue/page.tsx 기준으로 부모 폴더(revenue/)로 올라가려면 점 두 개(../), 그 위인 루트 src/ 폴더로 한 번 더 올라가려면 또 점 두 개(../)를 붙여 총 ../../를 쓴 뒤, components/Button 폴더로 진입해야 합니다.

4. AI에게 보내는 안전한 수정 요청문

바로 수정부터 시키지 말고, 아래 네 단계를 순서대로 요청하면 파일을 잘못 건드릴 가능성이 줄어듭니다.

1. 찾기

“이 화면과 관련된 페이지, 컴포넌트, 스타일 파일을 먼저 찾아 목록으로 보여줘.”

2. 설명

“각 파일의 역할과 서로 연결되는 관계를 초보자가 이해할 수 있게 설명해줘.”

3. 최소 수정

“새 패키지를 설치하지 말고, 필요한 파일만 최소 범위로 수정해줘.”

4. 검증

“변경된 파일 목록과 diff 요약, 브라우저에서 확인할 항목을 마지막에 정리해줘.”
