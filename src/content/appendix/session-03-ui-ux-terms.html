STUDENT HANDOUT · SESSION 03

프론트엔드 · UI/UX · 애니메이션 예시집

용어를 외우는 자료가 아닙니다. 내 프로젝트 화면을 AI에게 설명할 때 “무엇을 어디에서 어떻게 바꿀지” 찾는 텍스트 참고표입니다. 그림과 링크 없이 인쇄해서 사용할 수 있도록 구성했습니다.

1. 서비스마다 필요한 프론트엔드가 다릅니다

쇼핑몰검색창, 카테고리, 상품 카드, 장바구니, 결제, 주문 완료 화면확인 질문: 상품을 찾고 결제 완료까지 다음 행동이 계속 보이는가?
커뮤니티게시글 목록, 글쓰기, 댓글, 좋아요, 저장, 알림, 사용자 프로필확인 질문: 새 글과 새로운 반응을 발견하고 참여하기 쉬운가?
예약 서비스날짜, 시간, 인원 선택, 가격 확인, 예약자 정보, 예약 완료 화면확인 질문: 이미 고른 조건과 남은 단계를 잃어버리지 않는가?
관리자 화면통계, 검색, 필터, 표, 상태 배지, 상세 보기, 일괄 처리확인 질문: 지금 확인하거나 처리할 항목이 먼저 보이는가?
포트폴리오소개, 프로젝트 목록, 상세 과정, 사용 기술, 연락 방법확인 질문: 방문자가 짧은 시간 안에 강점과 결과물을 이해하는가?
SaaS 도구온보딩, 작업 화면, 설정, 저장 상태, 사용량, 요금제, 도움말확인 질문: 처음 온 사용자도 첫 결과를 만들 수 있는가?

2. UI: 화면에서 보고 누르는 부품

용어뜻AI에게 요청하는 예시
헤더로고, 주요 메뉴, 검색, 로그인 등이 있는 화면 상단.“헤더에 검색과 로그인 버튼을 정리해줘.”
내비게이션사용자가 다른 화면이나 구역으로 이동하는 메뉴.“현재 페이지가 표시되는 내비게이션을 만들어줘.”
버튼저장, 주문, 시작처럼 행동을 실행하는 요소.“가장 중요한 저장 버튼을 한눈에 보이게 해줘.”
입력창검색어, 이메일, 댓글처럼 값을 입력하는 칸.“입력 예시와 오류 메시지를 입력창 가까이에 보여줘.”
카드상품, 게시글, 프로젝트처럼 한 묶음의 정보를 담는 영역.“프로젝트 카드를 제목, 설명, 상태 순서로 정리해줘.”
모달현재 화면 위에 집중 작업을 띄우는 창.“삭제 전에 이유와 취소 버튼이 있는 확인 모달을 띄워줘.”
드로어화면 가장자리에서 밀려 들어오는 메뉴나 설정 영역.“모바일에서는 메뉴를 왼쪽 드로어로 열어줘.”
탭같은 화면에서 관련 내용을 나눠 전환하는 요소.“상세, 리뷰, 문의 탭의 현재 위치를 표시해줘.”
드롭다운누르면 선택지가 아래로 펼쳐지는 메뉴.“상태를 선택하는 드롭다운을 추가해줘.”
필터가격, 날짜, 상태 등 조건으로 목록을 줄이는 기능.“선택된 필터를 해제할 수 있는 칩으로 보여줘.”
표여러 데이터의 같은 항목을 행과 열로 비교하는 화면.“주문 번호, 고객, 상태, 금액을 표로 정리해줘.”
배지배송 중, 완료, 오류 같은 짧은 상태 표시.“주문 상태를 색만이 아니라 글자 배지로도 표시해줘.”
토스트저장 완료처럼 잠깐 나타나는 작은 결과 알림.“저장 후 우측 상단에 완료 토스트를 보여줘.”
빈 상태데이터가 없을 때 다음 행동을 안내하는 화면.“목록이 비었을 때 첫 프로젝트 만들기 버튼을 보여줘.”

3. UX: 사용자가 막히지 않도록 만드는 과정

상황불편한 경험좋은 경험
결제현재 단계와 최종 금액을 마지막까지 알 수 없다.진행 단계, 상품 금액, 배송비, 결제 후 결과를 미리 보여준다.
회원가입많은 입력칸과 약관을 한 화면에 한꺼번에 보여준다.필요한 정보만 단계별로 묻고, 왜 필요한지 설명한다.
검색결과가 없다는 문장만 보여주고 끝난다.오타 교정, 관련 검색어, 필터, 인기 항목을 제안한다.
오류 복구“오류가 발생했습니다”만 보여주고 입력 내용을 지운다.작성 내용을 유지하고 원인, 해결법, 다시 시도 버튼을 함께 준다.
로딩아무 변화가 없어 멈춘 것처럼 보인다.로딩 중임을 알리고 콘텐츠가 나타날 자리를 먼저 보여준다.
삭제한 번의 클릭으로 복구할 수 없이 삭제한다.확인 문구를 보여주거나 잠시 되돌리기 기능을 제공한다.
모바일버튼과 글자가 너무 작고 가로 스크롤이 생긴다.중요한 행동을 손가락으로 누르기 쉬운 크기와 순서로 재배치한다.
접근성색만으로 상태를 구분하고 글자 대비가 낮다.색, 아이콘, 글자를 함께 사용하고 충분한 대비를 유지한다.
UI는 “화면이 어떻게 생겼는가”, UX는 “사용자가 목표까지 막히지 않고 갈 수 있는가”입니다.

4. 화면 애니메이션 10종

예시무엇을 알려주는가주의할 점
메뉴 전환새 선택지가 어느 방향에서 이어지는지 보여준다.너무 느리거나 화면을 과하게 가리지 않는다.
스켈레톤 로딩콘텐츠를 불러오는 중이며 어디에 나타날지 알려준다.실제 내용과 비슷한 크기로 만든다.
장바구니 이동선택한 상품과 장바구니 숫자의 변화를 연결한다.장식보다 수량 변화가 분명해야 한다.
완료 전환작업이 끝났고 다음 행동이 가능함을 확신시킨다.성공 문구와 다음 행동을 함께 보여준다.
탭 전환같은 화면 안에서 현재 보고 있는 위치를 알려준다.선택 표시와 내용이 동시에 바뀌어야 한다.
입력 검증문제가 생긴 위치와 고쳐야 할 방법을 연결한다.빨간 흔들림만 사용하지 말고 설명을 적는다.
아코디언필요한 내용만 펼쳐 정보 밀도를 조절한다.열렸는지 닫혔는지 아이콘과 공간 변화로 보여준다.
페이지 전환목록에서 선택한 대상이 상세 화면으로 이어졌음을 보여준다.방향과 속도를 화면 이동의 의미에 맞춘다.
좋아요 반응작은 저장 행동이 실제로 반영되었음을 알려준다.아이콘, 숫자, 저장 위치가 같은 상태를 보여야 한다.
스크롤 진행긴 페이지에서 현재 위치와 남은 길이를 알려준다.내용을 가리지 않는 얇고 안정적인 표시를 사용한다.

5. 기능마다 확인할 화면 상태 6가지

기본아직 행동하지 않았을 때 무엇을 할 수 있는지 보인다.
처리 중클릭을 받았고 작업이 진행 중임을 알려 중복 실행을 막는다.
성공무엇이 완료되었고 다음에 무엇을 할 수 있는지 보여준다.
실패원인, 유지된 내용, 해결 방법, 다시 시도를 함께 보여준다.
빈 화면데이터가 없다는 말에서 끝내지 않고 첫 행동을 제안한다.
사용 불가권한, 조건, 입력 부족 때문에 누를 수 없다면 이유를 알려준다.
이동메뉴·탭·페이지가 어디로 이어지는지 설명
상태열림·닫힘·선택·로딩처럼 현재 상태를 표시
피드백저장·주문·좋아요의 결과를 즉시 확인
안내오류 위치·스크롤 위치·다음 행동을 강조
움직임을 넣기 전 “사용자가 이 움직임으로 무엇을 더 잘 이해하는가?”에 답할 수 있어야 합니다. 답이 없다면 애니메이션을 넣지 않아도 됩니다.

6. AI에게 요청하는 문장 예시

프론트엔드 전체“한국 사용자가 익숙하게 느끼는 화면으로 만들고, 헤더·검색·목록·상세·완료 상태를 실제 서비스처럼 구현해줘.”
UI 정리“중요한 버튼과 보조 버튼의 차이를 크기와 색으로 구분하고, 글자와 요소가 겹치지 않게 여백을 정리해줘.”
UX 개선“처음 온 사용자도 다음 행동을 알 수 있게 현재 상태, 다음 단계, 성공과 실패 결과를 화면에 표시해줘.”
애니메이션“메뉴가 열리는 위치와 저장 완료 결과를 이해할 수 있도록 200~400ms의 절제된 전환을 넣어줘.”
오류 복구“오류가 나도 입력값을 유지하고, 실패 원인과 해결 방법, 다시 시도 버튼을 같은 영역에 보여줘.”
모바일“모바일에서는 버튼을 누르기 쉬운 크기로 바꾸고, 표는 카드나 가로 스크롤로 안전하게 표현해줘.”

7. 내 프로젝트 화면 점검

가장 중요한 행동이 화면에서 먼저 보인다.
클릭 후 처리 중, 성공, 실패 상태가 모두 있다.
빈 화면과 사용할 수 없는 상태에서 이유와 다음 행동을 알려준다.
오류가 나도 입력한 내용이 가능한 한 유지된다.
현재 위치와 다음 단계가 화면에 표시된다.
애니메이션이 의미를 설명하고 과하게 반복되지 않는다.
작은 노트북과 모바일에서도 글자와 버튼이 겹치지 않는다.
색만이 아니라 글자와 아이콘으로도 상태를 구분한다.
수업에서 모든 용어를 외울 필요는 없습니다. AI에게 “어떤 서비스의 어느 화면에서 사용자가 무엇을 하며, 어떤 결과를 보아야 하는지” 설명할 수 있으면 됩니다.
