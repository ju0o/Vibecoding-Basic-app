INSTRUCTOR STUDY · SESSION 05

공개되는 순간 달라지는 것

강사용
학습 기준: Git/GitHub, Vercel/Firebase, 환경변수, 데이터 권한을 초보자에게 과장 없이 설명하고 실제 배포 오류의 위치를 구분한다.

1. 강사가 먼저 구분해야 할 여섯 개념

Git

파일의 변경 이력을 commit이라는 저장 지점으로 관리하는 분산 버전 관리 시스템입니다. 인터넷 연결 없이도 로컬 기록을 만들 수 있습니다.

GitHub

Git repository를 온라인에 호스팅하고 branch, pull request, issue, 배포 서비스 연동을 제공하는 플랫폼입니다.

Build

개발용 소스와 의존성을 브라우저나 서버가 실제 운영에서 실행할 형태로 변환·검사하는 과정입니다.

Deploy

성공한 build 결과를 서버와 URL에 연결해 사용자가 접속할 수 있게 만드는 과정입니다.

Environment Variable

환경마다 달라지는 설정값을 코드와 분리해 전달하는 방식입니다. 환경변수라는 이유만으로 자동 암호화되거나 비밀이 되지는 않습니다.

Authorization Rule

로그인 상태와 역할에 따라 누가 어떤 데이터를 읽고 쓰고 수정할 수 있는지 서버 쪽에서 강제하는 규칙입니다.

2. GitHub 기본 흐름

status

변경 파일 확인

add

commit 대상 선택

commit

로컬 저장 지점 생성

push

GitHub로 전송

설명 포인트: `git add .`부터 가르치지 말고 `git status`를 먼저 보여줍니다. 모든 변경을 한 번에 포함하기 전에 `.env`, 대용량 파일, 의도하지 않은 수정이 없는지 확인해야 합니다.

Vercel Git 배포

본 강의의 메인 공개 흐름입니다. 검증한 GitHub release를 기준으로 웹 build와 Production URL을 연결합니다. Framework, build command, output directory, 환경변수를 확인합니다.

Firebase Hosting

필요할 때 선택하는 대체 Hosting 경로입니다. `firebase init hosting`으로 로컬 폴더와 Firebase 프로젝트를 연결하고 `firebase deploy --only hosting`으로 공개할 수 있지만, 본문에서는 Vercel 웹 배포와 Firebase Auth·Firestore 연결을 하나의 release 흐름으로 설명합니다.

Preview와 Production

Preview는 변경을 검토하기 위한 임시 배포, Production은 실제 사용자가 접속하는 기준 배포입니다. 두 환경의 변수와 도메인이 다를 수 있습니다.

CLI와 Dashboard

CLI는 명령으로 연결·배포하고 Dashboard는 프로젝트 설정, 도메인, 환경변수, 로그를 관리합니다. 둘 중 하나만 아는 것이 아니라 역할을 구분합니다.

3. 비밀값 설명에서 가장 많이 틀리는 부분

`.env` 파일은 코드와 값을 분리할 뿐입니다. Git에 올리지 않고 서버에서만 읽을 때 비밀을 지킬 수 있습니다.
`.env.local`은 로컬 개발자의 실제 값이고, `.env.example`은 실제 값 없이 변수 이름만 공유하는 안내 파일입니다.
Next.js의 `NEXT_PUBLIC_`, Vite의 `VITE_` 변수는 브라우저 코드에 포함될 수 있으므로 비밀값에 사용하지 않습니다.
노출된 일반 API 키는 파일에서 삭제하는 것만으로 충분하지 않습니다. 키를 폐기하고 새로 발급합니다.
Firebase 웹 설정의 API key는 프로젝트 식별 용도로 공개되는 구조입니다. 데이터 권한은 Security Rules와 App Check로 보호합니다.
Gemini Developer API key, 결제 비밀키, 서비스 계정 키는 Firebase 웹 API key와 다르며 공개하면 안 됩니다.

4. 배포 실패 진단 순서

Local

`npm run build` 확인

Install

Node·패키지 버전

Build log

첫 오류와 파일 경로

Runtime

환경변수·도메인·권한

Q. 로컬에서는 되는데 배포 build가 실패합니다.

로컬에서 `npm run build`를 먼저 실행하고, Node 버전, 대소문자가 다른 파일 경로, 누락된 환경변수, package-lock 불일치를 확인합니다.

Q. 배포는 성공했는데 빈 화면입니다.

브라우저 Console과 Network, SPA 라우팅 설정, base path, 정적 자산 경로를 확인합니다.

Q. 로그인만 배포 후 실패합니다.

배포 환경변수, 인증 서비스의 허용 도메인, callback URL, Security Rules를 순서대로 확인합니다.

Q. GitHub에 키를 올렸다가 바로 지웠습니다.

커밋 기록과 복제본에 남을 수 있으므로 해당 키를 폐기·재발급하고, 필요하면 secret scanning 안내에 따라 기록 정리를 검토합니다.

5. 수업 전 직접 해볼 실습

테스트 저장소에서 `git status → add → commit → push`를 직접 한 번 실행합니다.
Vercel에서 저장소 연결부터 Preview/Production URL 생성까지 한 번 진행합니다.
Firebase 테스트 프로젝트에서 `init hosting → deploy --only hosting`을 한 번 진행합니다.
의도적으로 환경변수 하나를 빼고 build 또는 runtime 오류 로그를 수집합니다.
비회원·회원·관리자 권한표를 자기 말로 설명해봅니다.
