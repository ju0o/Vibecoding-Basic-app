01 · TEACHING POSITION

현재 과정 안에서 어디까지 다룰 것인가

Workflow Architect 안에서는 구조와 판단 기준을 가르치고, 직접 제작과 운영까지 들어가면 별도 전문과정으로 분리합니다.

주제현재 심화과정에서 다룰 깊이별도 과정으로 빼야 하는 신호강의 산출물
Skill반복 업무를 재사용 절차로 바꾸는 법. 트리거, 입력, 절차, 산출물, 검증 기준을 설명합니다.여러 Skill을 버전 관리하고, 스크립트·레퍼런스·배포 패키징까지 다루기 시작할 때개인 업무 Skill 설계서 1개
MCPAI가 외부 데이터·도구를 쓰는 연결 구조와 최소 권한, 승인 지점을 설명합니다.직접 MCP 서버를 만들고 인증, OAuth, 세션, 도구 스키마, 보안 테스트까지 다룰 때읽기 전용 MCP 권한표
Agent목표, 도구, 상태, 종료 조건, 사람 승인 지점이 있는 실행 루프를 설명합니다.평가, tracing, guardrail, handoff, 비용 측정과 운영 로그를 코드로 구축할 때단일 Agent 운영 설계도
Agent Team역할을 나누는 이유, 파일 소유권, 반환 형식, 최종 Reviewer를 설명합니다.여러 Agent를 병렬 실행하고 충돌 조정, worktree, PR 리뷰 게이트까지 운영할 때역할·권한·인수인계 표
강의 분리 기준: 학생이 “개념을 이해하고 도구를 선택하는 수준”을 넘어서 “직접 제작, 배포, 운영, 보안 검증”을 해야 한다면 별도 과정으로 빼는 것이 맞습니다. 이때는 AI Agent Systems Professional 6주 같은 과정으로 독립시키는 편이 강의 가치가 올라갑니다.
02 · CORE MENTAL MODEL

한 장으로 설명할 구조

수강생에게 처음 보여줄 대표 슬라이드는 기능 목록이 아니라 책임이 확장되는 흐름이어야 합니다.

Prompt이번 한 번의 목표와 제약을 전달합니다. 재사용 구조는 아닙니다.
Skill반복 업무의 절차와 검증을 필요할 때 불러오는 작업 규격입니다.
MCPAI가 외부 데이터, 도구, 서비스와 연결되는 통로입니다.
Agent목표를 계획, 실행, 관찰, 복구하는 루프입니다.
SubAgent읽기, 테스트, 리뷰처럼 독립 작업을 별도 맥락에서 처리합니다.
PluginSkill, Agent, Hook, MCP 설정을 설치 가능한 단위로 묶습니다.
슬라이드 모션: 처음에는 Prompt 하나만 켜고, 다음 버튼을 누를 때마다 Skill, MCP, Agent, Team 노드가 켜지게 합니다. 자동 재생하지 말고 각 단계마다 “추가된 능력”과 “사람이 새로 져야 하는 책임”을 같이 표시합니다.
03 · OFFICIAL STUDY ORDER

강사가 읽어야 할 공식자료 순서

수업 전에는 링크를 많이 모으는 것보다 어떤 순서로 읽어야 개념 경계가 잡히는지가 중요합니다.

1. MCP 개념

Model Context Protocol의 소개와 architecture를 먼저 읽습니다. 강의에서는 “AI용 USB-C” 비유를 쓰되, 반드시 권한과 도구 범위로 연결합니다.
modelcontextprotocol.io/docs/getting-started/intro

2. MCP 보안

연결 성공보다 confused deputy, token passthrough, SSRF, scope minimization 같은 위험을 먼저 이해합니다. 초보자 수업에서는 “읽기 권한부터 시작”으로 번역합니다.
modelcontextprotocol.io/docs/tutorials/security/security_best_practices

3. Skill 개념

Claude Code와 Codex 모두 Skill을 반복 가능한 작업 지침으로 다룹니다. 긴 프롬프트 저장소가 아니라 호출 조건, 자료, 절차, 검증 기준입니다.
code.claude.com/docs/en/skills

4. Agent 개념

OpenAI Agents SDK 기준으로 Agent는 instructions, tools, handoffs, guardrails, structured outputs 같은 런타임 동작을 가진 구성입니다. 강의에서는 “스스로 움직이는 마법”이 아니라 “상태를 가진 실행 루프”로 설명합니다.
developers.openai.com/api/docs/guides/agents

5. Handoff와 Team

전문 Agent에게 업무를 넘기는 handoff는 도구처럼 표현됩니다. 팀 강의에서는 manager 방식과 handoff 방식을 비교해야 합니다.
openai.github.io/openai-agents-python/handoffs/

6. Tracing과 운영

Agent 운영은 성공 화면보다 실행 기록이 중요합니다. LLM generation, tool call, handoff, guardrail을 추적하는 관점으로 실패 복구를 설명합니다.
github.com/openai/openai-agents-python/docs/tracing.md

04 · CONCEPT BOUNDARIES

수업 중 반드시 구분해야 할 차이

용어를 외우는 수업이 아니라, 어느 문제에 어떤 구조가 필요한지 판단하게 만드는 수업이어야 합니다.

SKILL

Skill은 언제 쓰는가

같은 절차를 계속 붙여넣고 있다면 Skill 후보입니다. 예: 코드 리뷰, 배포 전 점검, 이미지 최적화, 강의자료 QA.

  • 입력: 무엇을 받을지
  • 절차: 어떤 순서로 할지
  • 산출물: 무엇을 반환할지
  • 검증: 완료 기준은 무엇인지
MCP

MCP는 언제 쓰는가

AI가 현재 문서, 파일, 디자인, 이슈, 로그처럼 외부 시스템의 실제 정보를 읽거나 제한된 행동을 해야 할 때 씁니다.

  • 처음은 읽기 전용
  • 쓰기 작업은 승인 필요
  • 민감정보는 최소 권한
  • 도구 응답은 검증 가능해야 함
AGENT

Agent는 언제 쓰는가

한 번의 답변이 아니라 여러 단계를 수행하고, 중간 결과를 보고, 실패 시 복구해야 할 때 Agent 구조가 필요합니다.

  • 목표와 종료 조건
  • 사용 가능한 도구
  • 상태와 로그
  • 사람 승인 지점

07 · REHEARSAL CHECKLIST

수업 전 강사 리허설

전문 과정은 설명의 깊이보다 실패 복구 리허설이 강의 품질을 결정합니다.

DO

반드시 준비

  • 정상 흐름 캡처 1장, 실패 흐름 캡처 1장, 복구 후 캡처 1장
  • 공식자료 URL과 확인 날짜
  • 권한을 읽기에서 쓰기로 올리는 이유
  • 수강생이 따라 할 최소 실습 파일
  • 인터넷 실패 시 오프라인 대체 화면
DON'T

피해야 할 설명

  • “Agent가 알아서 다 해준다”
  • “MCP 연결하면 API를 몰라도 된다”
  • “Skill은 프롬프트 저장소다”
  • “Agent가 많을수록 좋다”
  • “보안은 나중에 붙이면 된다”

이 자료는 강사용입니다. 수강생에게는 각 과정의 실습 워크북과 체크리스트만 나눠주고, 공식자료 연구 순서와 강사용 실패 복구 메모는 강사자료실에서만 사용합니다.
