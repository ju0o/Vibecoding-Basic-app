# Roadmap — Phase별 구현 계획

## 구현 우선순위 원칙
1. **파이프라인이 콘텐츠보다 먼저다** — 강의 100개를 쓰기 전에 강의 1개가 파이프라인을 끝까지 통과하는 것을 증명한다.
2. **병목은 데이터 구조에서 온다** — 단일 파일(curriculum.ts, glossary.ts)이 커지기 전에 분리한다.
3. **검증 비용은 스크립트로 줄인다** — 같은 검사를 3번 하게 되면 스크립트로 만든다.

---

## Phase 1 — 파이프라인 검증 (지금 ~ 강의 20개)

목표: **강의 1개가 아이디어→배포를 완주**하고, 이후 배치 운영이 반복 가능해지는 것.

| # | 작업 | 담당 | 산출 |
|---|---|---|---|
| 1 | **git 저장소 초기화** (현재 미사용 — 병렬 운영의 안전망) | 운영자 + Codex | git init, .gitignore 정리, 첫 커밋 |
| 2 | 파일럿 1강 선정 (기존 backlog 없으므로 Curriculum Agent 첫 실행: P-02로 ai-system-design 모듈 분해) | Claude | BACKLOG.md |
| 3 | 파일럿 1강을 WF-01 전 단계로 완주 — 각 단계에서 프롬프트·규격의 문제를 발견하면 즉시 ai-ops 문서 수정 | 배정표대로 | 강의 1개 배포 + 문서 개정 |
| 4 | QA Gate 3의 기계 검사 스크립트화 (13섹션 제목, quiz answer 일치, slug 중복) | Cline/Codex | `ai-ops/qa/scripts/validate-content.mjs` |
| 5 | 배치 3~5개 운영 시작 (EXECUTORS.md의 하루 사이클) | 전체 | 주당 강의 3~5개 |

완료 기준: 강의 20개 배포, FIX 루프·에스컬레이션 경험 1회 이상 문서에 반영됨.

## Phase 2 — 대량 생산 체제 (강의 20 ~ 100개, 용어 ~1,000개)

목표: 데이터 구조를 규모에 맞게 바꾸고 생산 속도를 올린다.

1. **콘텐츠 데이터 구조 개편** (개발 작업 — Codex 배정):
   - LESSON_META를 강의 md의 frontmatter로 이전 → curriculum.ts는 모듈 정의만 남김 → **Site Integration의 순차 병목 해소** (강의 추가 = 파일 1개 추가)
   - glossary.ts → `src/content/glossary/{category}.json` 분리
   - 빌드 시 frontmatter 파싱·검증 (Zod 등) — Gate 3 일부가 빌드 검증으로 자동화
2. Illustration Agent 가동 (본문 내 SVG/Mermaid 렌더링 지원 추가)
3. WF-02 용어 대량 생산 가동 (카테고리 배치)
4. 노후화 점검(WF-03) 첫 회 실행
5. PIPELINE.md → slug별 status 파일 전환 (병렬 규모 증가 대응)

완료 기준: 강의 100개, 용어 1,000개, 통합 작업이 "파일 추가"만으로 가능.

## Phase 3 — 학습 경험 확장 (강의 100 ~ 300개, 용어 ~3,000개)

1. 실습 프로젝트 콘텐츠 타입 신설 (project-textbook 모듈용 — 13섹션과 다른 스키마 필요, 운영자 승인 후 schema 확장)
2. PDF 교재 생성 파이프라인 (배포된 md → 모듈별 PDF — Release Agent 확장)
3. 퀴즈 확장 (강의당 1문항 → 3~5문항, 스키마 확장)
4. AI 튜터 프로토타입 (배포 콘텐츠를 컨텍스트로 쓰는 질문응답 — 별도 설계 문서)

## Phase 4 — 플랫폼화 (강의 300개+)

1. 다국어 번역 파이프라인 — Translation Agent 신설 (원문 개정 시 번역 자동 무효화 추적이 핵심 설계)
2. 영상 강의 스크립트 파이프라인 (강의 md → 스크립트 → 슬라이드)
3. 사용자 계정·DB 진행률 (README 확장 방향과 연동)
4. 커뮤니티 피드백 → REVISION-BACKLOG 자동 유입

## 확장성 설계 근거 (왜 이 구조가 300강·3,000용어를 버티는가)

- **slug 단위 파일 독립성**: 강의가 늘어도 병렬 폭만 늘면 됨. 파이프라인 자체는 불변
- **Phase 2 frontmatter 전환**: 유일한 순차 병목(curriculum.ts)을 제거 — 이것이 확장의 관문
- **Executor 독립성**: 모델 세대가 바뀌어도 EXECUTORS.md 표 수정만으로 대응
- **게이트 스크립트화**: 콘텐츠 양이 늘수록 기계 검사 비중을 높여 검증 비용을 선형 이하로 유지
- **콘텐츠 = Markdown + 규격 파일**: PDF·영상·번역·AI 튜터 모두 같은 원천(md)에서 파생 — 원천을 하나로 유지하는 것이 다매체 확장의 전제
