# Knowledge Score — KB 품질 평가 기준

KB 문서가 `approved`가 되기 위한 정량 기준. P-02(검증)의 마지막 단계에서 산출하며, **미달 시 자동으로 재수집 루프(P-03)가 발동**된다.

## 필수 게이트 (점수 무관 — 하나라도 실패 시 즉시 재수집)

- [ ] G1. 출처 확인 불가(BLOCK) 주장 0건
- [ ] G2. 13개 필수 섹션 전부 존재
- [ ] G3. frontmatter 필수 필드 완전 (id, topicGroup, level, sources, updated)
- [ ] G4. sources의 모든 URL이 접속 가능하고 확인 날짜 존재

## 점수표 (100점 만점, 통과선 **80점**)

| # | 기준 | 배점 | 5단계 평가 기준 (배점 × 0/0.25/0.5/0.75/1.0) |
|---|---|---|---|
| S1 | 공식 출처 | 20 | 모든 사실 주장에 출처 + 공식 비중 60%↑ = 1.0 / 일부 주장 무출처 = 0.5 이하 |
| S2 | 최신성 | 15 | 전 출처 확인 날짜 6개월 이내 + 버전 의존 정보에 기준 표기 = 1.0 / 12개월↑ 방치 = 0.25 |
| S3 | 교육 적합성 | 15 | 정의가 무전문용어 + prerequisites 논리적 + level 적정 = 1.0 |
| S4 | 예시 품질 | 10 | 실무 활용의 예시가 구체적·실행 가능 = 1.0 / 추상적 나열 = 0.25 |
| S5 | AI 시대 연관성 | 10 | 바이브코딩 실무와 구체 연결 = 1.0 / 일반론("중요합니다") = 0.25 |
| S6 | 실무 활용성 | 15 | 사용 장면 2개↑ + 자주 하는 실수가 실제 오개념 = 1.0 |
| S7 | 용어 일관성 | 15 | 표기가 glossary 표준과 일치 + related/prerequisites id 실존 = 1.0 |

## 판정과 루프

```
점수 ≥ 80 그리고 필수 게이트 전부 통과
  → status: approved, frontmatter score 기록 → Lesson 생성 가능 (P-04)

점수 < 80 또는 게이트 실패
  → reviews/{id}/recollection-request-{n}.md 자동 생성 → Trae 재수집 (P-03)
  → 재수집 후 P-02 재평가 (전 항목이 아니라 미달 항목 중심)

루프 상한: 2회. 3회째 미달 → status: escalated, 운영자 판단
  (에스컬레이션 사유 예: 공식 출처 자체가 부재한 주제 → 주제 범위 재정의 필요)
```

## 재수집 요청서 규격 (`reviews/{id}/recollection-request-{n}.md`)

```
# 재수집 요청: {id} (루프 {n}/2)
## 현재 점수: {점수} / 미달 기준: S1, S4 ...
## 항목별 지시
| 기준 | 감점 사유 | 구체적 보강 지시 (어느 섹션에 무엇을) |
## 금지: 이미 통과한 섹션 임의 수정
```

**요청서 작성 규칙**: "더 좋게"가 아니라 실행 가능한 지시만 — 어느 섹션에, 어떤 종류의 출처/예시를, 몇 개. Trae가 판단 없이 수행할 수 있는 수준으로.

## 재평가 규칙
- 미달 기준만 재평가하되, 재수집이 다른 섹션을 건드렸으면 그 섹션 관련 기준도 재평가
- 필수 게이트는 매회 전체 재확인 (수정 중 새 무출처 주장이 생길 수 있음)

## 노후화 재평가 (운영 중)
- sources `checked`가 6개월 경과한 approved 문서는 status: stale 후보 → 분기 점검(WF-03 통합)에서 S2만 재평가, 미달 시 재수집 루프
