# SK-04 Source Verification (출처 검증)

Fact Check Agent의 핵심 절차. Research Agent도 브리프 작성 시 자기 검증용으로 쓴다.

## 검증 대상 분류
| 유형 | 예 | 검증 방법 |
|---|---|---|
| 수치·연도·버전 | "2015년 등장", "v15부터" | 출처 원문에서 해당 숫자를 직접 확인 |
| API·문법 | 함수 이름, 옵션, 코드 | 공식 레퍼런스 대조 + 코드 실행/정적 검토 |
| 인과 주장 | "~때문에 생겼다" | 공식 문서·발표문에 같은 인과가 있는지. 없으면 "일반적으로 ~로 알려져 있다"로 완화 요구 |
| 비교 주장 | "A가 B보다 빠르다" | 조건 없는 비교는 FIX — 조건을 붙이거나 삭제 |
| 정의 | 용어 뜻 | 표준 문서의 정의와 의미 일치 확인 |

## 판정 규칙
- `PASS`: 출처 원문에서 확인됨
- `FIX`: 방향은 맞지만 부정확 (숫자, 뉘앙스, 조건 누락) — **반드시 수정 문장을 제시**
- `BLOCK`: 어떤 허용 출처에서도 확인 불가 — 삭제 요구. 작성자가 이의를 제기하면 출처를 가져오게 한다 (입증 책임은 작성자)

## 절차
1. 초안에서 사실 주장 문장을 전부 추출해 번호를 붙인다 (의견·비유는 제외하되, 비유가 사실을 암시하면 포함)
2. 각 문장을 브리프의 출처와 1차 대조
3. 브리프에 없는 주장은 웹에서 공식 출처 탐색 (SK-01의 출처 우선순위 적용)
4. 코드 예시: 실행 가능하면 실행, 아니면 공식 레퍼런스로 문법·API 검토. 검증 방법을 보고서에 명시
5. 보고서 작성 (fact-check-agent.md 출력 규격)

## 원칙
- **자기 기억을 출처로 쓰지 않는다.** "내가 알기로 맞다"는 PASS 사유가 될 수 없다.
- 확인 날짜를 기록한다 — 6개월 뒤 노후화 점검(WF-03)의 기준이 된다.
