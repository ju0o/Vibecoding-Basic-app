# SK-02 Deep Dive Writing (심층 집필 규칙 — V2)

> 2026-07-05 O-04로 전면 개정. 구 버전(입문 교재체·13섹션·비유 의무)은 git 이력 참조. 형식 규격은 [CONTENT-FORMAT-V2.md](../roadmap/CONTENT-FORMAT-V2.md)가 우선.

## 독자 모델
- **깊이를 원하는 학습자** — 요약본이 아니라 전문가의 이해에 도달하고 싶은 사람. 공식 문서를 직접 읽을 수 있게 되는 것이 목표
- 얕은 반복 학습 장치(퀴즈 등)는 없다 — 본문 자체가 전부다

## 문체 규칙
1. 경어체("~합니다") 유지. 단 설명 밀도를 희생하지 않는다 — 한 문단이 하나의 기술적 사실을 끝까지 파고든다
2. **"어떻게"와 "왜 그렇게 설계됐는가"가 본문의 중심.** "X는 Y다" 수준의 정의 나열 금지 — 정의 뒤에는 반드시 메커니즘이 따라온다
3. 전문 용어는 회피하지 않고 사용한다. 첫 등장 시 한 줄 풀이 후, 이후로는 원어 그대로
4. 비유는 의무가 아니다 — 메커니즘 이해를 실제로 앞당길 때만, 깨지는 지점 명시와 함께
5. 늘리기 수사 금지: "매우 중요합니다", "꼭 기억하세요" 류의 빈 문장 0개. 분량은 세부·인용·사례로만 채운다

## 인용 사용법 (V2의 심장)
- KB Quote Bank에서만 가져온다 (재검색 금지)
- 인용은 장식이 아니라 **논증의 근거** — 본문 주장 → 원문 인용 → 해설("이 문장이 말하는 것은, 우리 맥락에서는...") 순서
- 번역은 직역보다 정확한 의역 — 단 원문의 기술적 뉘앙스(autonomously, may, must 등)를 보존

## 하이라이트 사용법
- `==구절==`은 "이 문단에서 하나만 남긴다면" 기준 — 결론이 아니라 **판단 기준·수치·조건**을 우선 (예: ==토큰이 늘수록 회상 정확도는 떨어진다==)
- 상한 엄수: 문단당 1, 섹션당 3. 하이라이트가 많은 글은 하이라이트가 없는 글이다

## 코드 예시
- 실행 가능한 완결 형태, 실제 라이브러리·실제 API 사용 (의사코드 금지 — 스펙 섹션 제외)
- 주석은 "무엇"이 아니라 "왜 이 옵션인가"
- 실패하는 예시도 좋다 — 에러 메시지와 원인 분석 포함 시

## 섹션별 무게 배분 (8,000자 기준 가이드)
