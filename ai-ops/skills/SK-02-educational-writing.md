# SK-02 Educational Writing (교육적 글쓰기)

이 사이트의 강의 문체 규칙. Lesson Writer가 주로 쓰고, Education Review가 판정 기준으로 재사용한다.

## 독자 모델
- 개발 경험이 거의 없지만, **배운 것을 남에게 설명하는 것이 목표**인 성인 학습자
- 한 강의 = 35~50분, 앉은 자리에서 완독 가능해야 함

## 문체 규칙
1. **경어체 통일**: "~합니다/~입니다". 기존 강의(`src/content/lessons/markdown/`)와 톤을 맞춘다.
2. **새 용어는 등장 즉시 한 줄 풀이**: "MCP(AI가 외부 도구와 대화하는 표준 연결 방식)는 …"
3. **비유 작성 3원칙**:
   - 일상 소재 (식당, 택배, 도서관 수준의 보편 경험)
   - 개념의 **구조**와 대응돼야 함 (분위기만 비슷한 비유 금지)
   - 비유가 깨지는 지점을 "다만 ~ 점은 다릅니다"로 명시
4. **문단 규칙**: 한 문단 = 한 생각, 4문장 이내. 목록을 남발하지 말고 흐름이 필요한 곳은 문장으로.
5. **코드 예시 규칙**: 10~20줄, 주석은 한국어, 복사해서 실행 가능한 완결 형태. 입문 강의는 결과(출력)를 함께 보여준다.
6. **"AI 시대에서의 의미" 섹션**: 이 개념이 AI 바이브코딩 실무(프롬프트, 검증, 에이전트 설계)와 어떻게 연결되는지를 반드시 구체적 상황으로 쓴다. 일반론("AI 시대에 중요합니다") 금지.

## 13섹션 분량 가이드
| 섹션 | 분량 |
|---|---|
| 오늘 배울 것 / 한 줄 정의 | 각 2~4문장 |
| 쉬운 비유 / 왜 생겼는가 / 어떤 문제 해결 | 각 1~2문단 |
| 핵심 개념 | 개념 3~6개, 각 1문단 — 가장 긴 섹션 |
| 실제 예시 / 코드 예시 | 사례 1~2개 + 코드 1블록 |
| AI 시대에서의 의미 / 자주 헷갈리는 것 / 실무에서 쓰는 방식 | 각 1~2문단 |
| 공부 체크리스트 | "~를 설명할 수 있다" 3~5개 |
| 참고 출처 | 링크 3~6개 |
