# SK-08 Terminology Writing (용어 집필)

Terminology Agent의 집필 규칙.

## 정의 작성 2단계
1. **shortDefinition (한 문장)**: "X는 ~하는 ~이다" 구조. 다른 전문 용어 없이 읽혀야 한다. 검색 결과·카드에 노출되므로 60자 이내 권장.
2. **explanation (3~5문장)**: 왜 필요한가 → 어떻게 동작하는가 → 어디서 만나는가. 강의 본문의 압축이 아니라 독립적으로 읽히는 글.

## 표기 규칙
- term 표기: 영문 원어가 통용되면 `영문 (한글)` 형태 — 예: `Context Window (컨텍스트 윈도)`. 한글 번역이 지배적이면 한글 우선. **한 번 정한 표기는 사이트 전체 표준이 된다.**
- category: 기존 glossary.ts의 카테고리를 먼저 확인하고 재사용. 새 카테고리는 status에 제안으로 표시.
- related: 실제 존재하는 용어만. 이번 배치에 포함된 용어면 `(이번 배치)` 표시.

## 중복·충돌 처리
- 같은 개념 다른 표기 발견 → 새로 만들지 말고 기존 항목에 별칭 제안
- 기존 정의가 부정확하다고 판단 → 수정하지 말고 `status: conflict`로 보고 (개정은 WF-03)

## 대량 생산 시 (WF-02)
- 배치 내 용어 간 related를 상호 연결해 그래프를 만든다 (고립 용어 최소화)
- 같은 카테고리 안에서 정의 문형을 다양화한다 (전부 "~하는 기술이다"로 끝나지 않게)
