### 2.3 설계 이슈

1. **비공개 모드 A vs 공개 모드 B** (`CITATION-POLICY.md`): 현재 인용이 비공개 전제. 공개 시 인용 축약·attribution 작업이 제품 게이트.  
2. **교육 목표 vs 제품 형태**: 목표는 “원리 이해 + 실습 감각”이나 제품은 **장문 교재 리더** 중심. 실습 루프(터미널·에이전트·PR)는 콘텐츠 설명으로만 존재.  
3. **getting-started 모듈 4강** (맵은 5강 목표) — 커리큘럼 맵과 실제 카운트 불일치.  
4. **홈 Feature 카피** “체크리스트” — 상태 모델은 있으나 학습자 UX로 드러나지 않음 → 기대 불일치.

### 2.4 UX / 교육 흐름

| 문제 | 영향 |
|---|---|
| 단강 35–70분·심층 장문 | 초보자 피로; 오프라인 1회 세션에 1–2강도 과할 수 있음 |
| 모듈 순서 점프 가능 | 자유 탐색 좋음, “필수 선행” 강제/시각화 약함 |
| 영·한 혼용 본문 | 비개발 초보에게 인지 부하 (특히 HTTP/MCP 계열) |
| 복습·스페이스드 리피트 없음 | 완료 버튼만으로 장기 기억 지원 약함 |
| 과제/루브릭 없음 | 코호트 운영 시 강사 부담 전가 |

### 2.5 용어 설명

- 용어 사전 **456**항 — 양호.  
- 본문 중 용어 자동 링크 **확인 필요**(Glossary와 lesson markdown 자동 연결 여부: 별도 컴포넌트 링크 생성 미확인 시 수동 의존).  
- 초보 난이도 표기(입문/기초/중급)는 있으나 “왜 중급인지” 선행 조건 표시 약함.

### 2.6 초보자가 막히기 쉬운 지점 (표본 기반)

1. **MCP/Agent/Harness** 모듈: 추상 구조 + 템플릿 문단 → 그림·인터랙션 없이 이해 어려움.  
2. **HTTP 강의**: 개념은 좋으나 영문 기술 명사 밀도 높음.  
3. **전체 103시간 분량**: “마스터” 기대와 실제 소요 시간 안내 부족.  
4. **비밀번호 게이트**: 프로덕션에서 해시 미설정 시 잠금 안내 — 배포 체크리스트 필수.

### 3.3 보강 우선순위

| 유형 | 위치/예시 | 권장 |
|---|---|---|
| **설명 부족** | MCP host/client/server 역할이 서로 다른 구체 시나리오로 안 갈림 | 1개 시나리오(예: “강의 검색 도구 연결”)로 역할 분담 표 |
| **예시 부족** | 추상 원리 소절이 코드/화면 증거 없이 끝나는 경우 | Before/After 프롬프트, Network 탭 스크린(자체 촬영) |
| **애니메이션 필요** | request→response, agent loop, RAG 검색 | 3–5초 루프 GIF/SVG animate 또는 단계 토글 UI |
| **그림 필요** | 다이어그램 없는 22강 (AI 시스템 축 중심) | 기존 78 SVG 스타일로 보충 |
| **실습 필요** | Git/HTTP/배포/바이브 루프 | “5분 실습 카드”: 할 일 3개 + 성공 증거(스크린/로그) |
| **템플릿 문장 제거** | 9강+ “독립된 체크박스…” 반복 | 강별 고유 원리 문단으로 재작성 |
| **언어 밀도** | HTTP 등 | 한 문단 1개념, 영문 용어 첫 등장 시 한글 풀이 고정 |

### 3.4 콘텐츠 파이프라인 평가

- KB → 강의 → 통합 → verify → release 흐름은 **운영 자산으로 강점**.  
- 기계 QA·인용 대조 문화는 교육 신뢰에 기여.  
- 다만 **생성 템플릿 동질성**이 일부 심층 강의 품질을 깎음 → “형식 PASS ≠ 교육 PASS” 게이트 추가 권장.

## 7. 프로젝트 확장 방향 (Vibe Coding 2차 프로그램)

### 7.1 현재 프로젝트와의 연결성: **높음 (자연 연결)**

| 2차 주제 | 현재 위치 | 연결 평가 |
|---|---|---|
| Claude Code / Codex / Cursor / Cline / Gemini CLI | 모듈 `ai-coding-tools` 강의 다수 | 이미 개념 교재 존재 → 2차는 **실습 랩** |
| AI IDE / Agent / Sub-agent | `ai-system-design`, practical 모듈 | 이론→도구 워크숍으로 확장 |
| MCP / Skills / Workflow | MCP·Skills 관련 강의 | 다이어그램·실습 샌드박스 보강 필요 |
| Context / Harness / Loop / Orchestration | 동명·유사 slug 다수 | 1차가 어휘, 2차가 체화 |
| 개발 원리(FE/BE/DB/Git/Deploy/보안) | 모듈 1–7 | **1차 필수 선행**으로 고정 가능 |

**결론:** 현재 사이트는 “**왜 이런 구조가 생기는가**”의 **이론·어휘·검증 태도** 레이어다.  
2차 “비개발자를 위한 Vibe Coding”은 같은 커리큘럼 맵 위에 **도구·에이전트·워크플로 실습**을 얹으면 된다. 브랜드·모듈 ID·용어 사전을 공유하면 학습 경로가 끊기지 않는다.

### 7.2 간극 (1차만으로 부족한 것)

- 실제 CLI/IDE 설치·권한·샌드박스  
- 멀티 에이전트 오케스트레이션 체험  
- 실패 루프(테스트 빨강→수정)의 체감  
- 팀 워크플로(PR, review agent)  
- 인터랙티브 시각화(토큰 윈도, 툴 콜 트레이스)

## 8. 신규 프로젝트 설계 — 「비개발자를 위한 Vibe Coding」

### 8.1 비전

비개발자가 AI 코딩 에이전트와 **안전하게 협업**하여, 작은 제품을 “요청 → 구현 → 검증 → 설명” 루프로 끝까지 끝내는 힘을 기른다.  
1차 사이트가 **지도**라면, 2차는 **운전 연습장**이다.

### 8.2 목표

1. 도구별 역할(챗/IDE/CLI/에이전트)을 구분한다.  
2. Context·Skills·MCP·권한 경계를 그림으로 이해한다.  
3. 동일 요구사항을 2개 이상 도구로 구현·비교한다.  
4. 모든 산출물에 human review·테스트·출처 습관을 붙인다.  
5. 1차 교재의 개발 원리 용어로 자신의 작업을 설명할 수 있다.

### 8.3 대상 사용자

| 세그먼트 | 니즈 |
|---|---|
| 비개발 PM/디자이너/운영 | 스펙을 에이전트 작업으로 번역 |
| 비전공 창업자 | MVP를 검증 가능하게 제작 |
| 1차 수료생 | 이론을 도구 실습으로 전환 |
| **비대상** | 즉시 대규모 프로덕션 보안/규정 준수 엔지니어링 (고급 트랙) |

### 8.4 핵심 기능

1. **인터랙티브 시뮬레이터:** 에이전트 루프, 툴 콜, 권한 승인 플로우  
2. **미션 보드:** 요구사항 카드 → 단계 체크 → 증거 업로드(로그/스크린)  
3. **듀얼 도구 랩:** 같은 미션을 Cursor vs Claude Code 등으로 수행  
4. **컨텍스트 빌더 UI:** 파일/제약/완료조건 드래그 구성 → 프롬프트 프리뷰  
5. **MCP 플레이그라운드(샌드박스):** 가짜 tools/resources  
6. **검증 게이트:** 테스트 통과·설명 녹음/텍스트 제출 전 다음 미션 잠금  
7. **1차 교재 딥링크:** 막힐 때 원리 강의로 점프  
8. **강사 대시보드(코호트):** 미션 완료율 (계정 도입 시)

### 9.1 문서 정보

| 항목 | 내용 |
|---|---|

### 9.2 문제 진술

비개발자는 에이전트 도구를 켜도 (1) 무엇을 맡길지, (2) 어떤 맥락을 줄지, (3) 결과를 어떻게 검증할지 모른다.  
1차 교재는 원리를 주지만 **손맛·루프·도구 차이**를 체화시키기엔 정적이다.

### 9.3 목표 / 비목표

**목표**

- G1. 학습자가 미션 10개를 성공 증거와 함께 완료  
- G2. 동일 미션을 서로 다른 도구로 1회 이상 비교  
- G3. 매 미션 human review 체크리스트 100% 자기 보고  
- G4. 1차 강의 딥링크로 원리 복습

**비목표 (v1)**

- 클라우드 IDE 완전 호스팅  
- 자동 코드 채점 LLM 재판관(보조만)  
- 멀티테넌트 엔터프라이즈 SSO (P3+)

### 9.4 사용자 스토리 (발췌)

1. 학습자로서 미션 카드를 보고 성공 증거를 이해한 뒤 시작한다.  
2. 학습자로서 컨텍스트 빌더로 파일/제약을 고르고 프롬프트를 복사한다.  
3. 학습자로서 에이전트 루프 시뮬에서 잘못된 도구 호출을 거부한다.  
4. 학습자로서 완료 전 “한 줄 설명”을 제출한다.  
5. 강사로서 코호트 미션 완료율을 본다.  
6. 학습자로서 막히면 1차 강의 `http-request-response` 등으로 이동한다.

## 10. 최종 의견

### 판정: **GO WITH FIXES**

### 이유 (확실한 것)

1. **제품 코어는 동작 가능한 교재 사이트다.**  
   - 강의 md **100**, 커리큘럼 모듈 **13**, 용어 **456**, 정적 export·`out/lessons` **100** HTML, 테스트 **8/8 통과**(본 세션 `npm run test`).  
   - 역사적 verify 기록: `ai-ops/outputs/06-build-verification/*`, HANDOFF의 verify exit 0 서술.

2. **교육 설계가 프로젝트 목적과 정합한다.**  
   - 개발 원리 → AI 시스템 순서, 검증·인용·설명 가능성 강조. “AI 사용법 앱”이 아니다.

3. **비공개 운영 장치는 코드에 존재한다.**  
   - PasswordGate, `robots.txt` Disallow 전체, metadata noindex, DEPLOY-GUIDE.

4. **공개·법적·품질 마감은 미완이다.**  
   - LICENSE 없음, Privacy/Terms 없음, favicon/OG 이미지 없음.  
   - 인용 공개 모드 B 전수 정리 미완(`citation-review` 빈약).  
   - README/기능 약속 드리프트, 다이어그램 22강 공백, 일부 강의 템플릿 반복.  
   - 클라이언트 게이트는 보안 경계가 아님(문서도 인정).

5. **Firebase 실배포는 운영자 보류** — 본 판정은 “라이브 URL이 이미 완벽”을 의미하지 않는다.  
   - HANDOFF는 커밋·deploy 잔여를 명시. STATE의 “라이브 100” 표현과 불일치 → 배포 여부 **확인 필요**.

6. **2차 Vibe Coding 프로그램은 1차 위에 자연스럽게 쌓을 수 있다.**  
   - 다만 2차는 별도 인터랙티브 제품(본 보고서 §8–9)으로 가는 것이 맞다.

### GO / HOLD가 아닌 이유

| 대안 | 기각 사유 |

| **HOLD** (전체 중단) | 비공개 코호트·오프라인 교재·내부 배포 목적에는 이미 충분한 가치; 빌드·콘텐츠 양 확보 |

#### 확실한 것

- 소스 기준 강의 100, 모듈 13, V2 8섹션 스키마.

- 퀴즈 페이지·Privacy/Terms·루트 LICENSE·favicon은 현재 트리에 없음.  
- 본 세션에서 제품 코드 구현 변경 없음(보고서 작성 목적).
