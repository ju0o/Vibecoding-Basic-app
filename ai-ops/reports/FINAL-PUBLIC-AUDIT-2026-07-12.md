## 1. Executive Summary

AI Vibe Coding Master는 비개발자에게 **AI가 만들어 내는 개발 구조(FE/BE/DB/API/Git/배포/보안 및 AI 시스템 개념)** 를 설명하는 **무료 교재형 정적 사이트**다.  
제품 실체: **강의 Markdown 100 · 모듈 13 · 용어 456 · SVG 다이어그램 78 · 정적 export 100 HTML · Vitest 8/8 PASS**(본 세션 재실행).

**교육 설계는 이미 “최고 무료 자료” 후보 수준**이다. 그러나 **현재 기술 모드는 비공개(모드 A)** 다: `PasswordGate` + `robots.txt Disallow: /` + `noindex`. 인용 정책도 공개 모드 B 전환 절차를 전제로 한다.

**무료 공개 판정: GO WITH FIXES**

- **공개를 영원히 막을 결함은 아니다.** 콘텐츠 양·구조·검증 파이프라인은 공개 가치가 충분하다.  
- **공개 당일 전에 반드시 닫아야 할 법적·정책 게이트**는 있다: 인용 모드 B, LICENSE, Privacy/Terms(또는 최소 고지), 게이트/index 전환, README 정합, 저작권 고지.  
- **공개 후 개선해도 되는 것**과 **공개 전 필수**를 분리하면, 완벽주의로 공개가 무기한 지연되는 함정을 피할 수 있다.

**CodingLabV2**(`ai-ops/CodingLabV2.md`)는 애니메이션 튜토리얼 + 브라우저 IDE + 진도 + 커뮤니티를 담은 **작성 중 PRD**다. 브랜드상 “Vibe 코딩”을 공유하나, 문서 본문은 **변수·함수 등 일반 코딩 기초의 모션 학습**에 가깝고, 사용자가 기대한 **Claude Code / Cursor / Agent / MCP 실습 랩**과는 범위가 어긋날 위험이 있다.  
**권고 순서:** ① Master **무료 공개 픽스 → 공개** ② CodingLabV2 **범위 재정렬(Master 보완재로)** ③ Agent/Workflow/Orchestration/AI Company 트랙.

## 3. GO / GO WITH FIXES / HOLD

### 판정: **GO WITH FIXES**

| 대안 | 기각 이유 |
|---|---|
| **GO** | 모드 B 인용 정리·LICENSE·법적 고지·게이트/index 전환 없이 “지금 당장 전체 공개”는 정책 위반 및 리스크 |
| **HOLD** | 100강·빌드·교육 설계가 이미 공개 가치 충족. 무기한 홀드는 완벽주의 함정 |

### 근거 (확실한 것)

1. 콘텐츠·사이트 코어는 존재하고 테스트/정적 export가 뒷받침한다.  
2. 교육 목적이 “AI 사용법 앱”이 아니라 **개발 원리**로 일관된다.  
3. 공개를 막는 **구조적 제품 실패는 없음**.  
4. 공개를 막는 **정책·법무·모드 전환 미완은 있음** (`CITATION-POLICY` 모드 A, LICENSE 부재, Privacy/Terms 부재, PasswordGate+noindex).  
5. Firebase 라이브 URL이 100강인지 여부는 공개 가능 여부의 **필수 조건이 아님**. (배포는 픽스 후 실행 가능. 라이브 상태는 **확인 필요**.)

### 공개 시나리오 매핑

| 시나리오 | 판정 적용 |
|---|---|
| 비밀번호 유지 비공개 | 이미 가능 (별 이슈) — 본 감사 대상 아님 |

- 주요 직접 의존성 MIT(또는 명시 dual/Apache).  
- 제품 `public/`에 외부 이미지 팩 없음.  
- 인용 정책 문서가 공개 전 정리 절차를 이미 정의함.  
- 루트 LICENSE·Privacy·Terms **없음**.

### 6.3 확인 필요

- 100강 인용 길이·문서당 개수가 모드 B 기준을 만족하는지.  
- MDN 인용 전건 CC 표기 여부.  
- AI 생성 텍스트/SVG의 저작권 귀속 정책(운영 계약).  
- 폰트 파일 재배포 고지 문구 최종본.  
- 상용 교육 이용 시 로컬 법무 해석(한국 공정이용 등).

### 6.4 저작권 — 공개 전 반드시 수정 목록 (저작권 only)

1. 모드 B 기준 긴 인용 축약·삭제·재서술 + 출처 URL 유지.  
2. LICENSE(코드) + 콘텐츠 이용 조건(교육 목적 무료, 재배포 조건).  
3. Third-party notice (MIT 목록).  
4. 폰트 라이선스 고지(확인 후).  
5. CC-BY-SA 인용 표기 누락분 수정.  
6. (해당 시) 외부 코드/도표 잔존분 제거 또는 재작성.

## 7. 운영 감사 결과

### 7.1 무료 사이트로 운영 가능한가?

**예 — 단, “저인양 운영” 모델로.**  
정적 호스팅 + Markdown 원천 + 로컬 진행률은 서버비·CS 부담이 낮다.  
ai-ops 파이프라인은 콘텐츠 갱신에 강력하나, **공개 후 운영 문서가 생산 파이프라인에 치우쳐 있고 “유저 대면 운영” 런북이 부족**하다.

### 7.2 부족한 점

| 영역 | 현황 | 갭 |
|---|---|---|
| 상태 단일 진실 | STATE vs DASHBOARD 숫자 불일치 | 공개 전 DASHBOARD 재생성 또는 “읽지 말 것” 표시 |
| 배포 | DEPLOY-GUIDE는 비공개 모드 | 공개 모드 체크리스트 별도 필요(§4) |
| 피드백 | 제품 내 이슈 제보 없음 | GitHub Issues / 폼 1개 |
| 지표 | Analytics 없음 | 공개 후 익명 pageview면 충분 |
| 커뮤니티 | 없음 (의도적 단순) | Discord/카톡 강요 금지, FAQ+이슈로 시작 |
| 업데이트 | M4 리프레시·CONTENT-REFRESH 문서 존재 | 달력(월 1회 stale KB)만 운영자 캘린더에 고정 |
| 문서 부채 | ROADMAP Phase1 잔상, PIPELINE superseded, zip 아카이브 | 정리로 인지 부하 감소 |

### 7.3 관리 포인트 (운영자 최소 동작)

운영 매뉴얼 철학 유지: **사람은 승인·공개 스위치·에스컬레이션만.**

| 주기 | 동작 |
|---|---|
| 공개 당일 | §4 체크리스트 → 배포 → 스팟 5 URL |
| 주 1 | 이슈 함 확인, 깨진 링크 1건이라도 수정 |
| 월 1 | M4 stale-KB 스캔 미션 실행(Codex) |
| 분기 1 | 도구 변화 큰 강의 3~5개 리프레시 |
| 상시 | 외부 삭제 요청 → citation-review 경로 |

### 7.4 업데이트 방식 (권고)

1. **원천 = Markdown + KB** 유지 (ROADMAP 취지).  
2. 변경은 기존 P-04→P-05→verify→release.  
3. 공개 브랜치: `main` = 공개 가능 상태만.  
4. “핫픽스 카피”는 운영자가 직접 짧은 PR (정책 허용).

### 7.5 커뮤니티 참여 방식 (저비용)

| 단계 | 방식 |
|---|---|
| v1 공개 | 푸터 “오류·개선 제안” → GitHub Issues 템플릿 3종(오탈자/내용/기능) |
| v1.1 | 강의 하단 “이 설명이 도움이 됐나요?” 이진 피드백(로컬 또는 익명 endpoint) |
| v2 | 우수 질문 FAQ화 (사람이 큐레이션) |
| 하지 말 것 (초기) | CodingLabV2 수준의 풀 포럼·좋아요·멘션 — 운영 폭발 |

### 7.6 Batch 1 교훈 → 공개 운영

- 파이프라인 자동화는 성공 (100강).  
- **문서 현황판 자동 갱신이 끊기면 대시보드가 거짓말**한다 → 공개 후 “STATUS = STATE only”로 단순화.  
- 배포만 사람 — 무료 공개의 유일한 큰 스위치로 유지.

### 8.4 교육 품질 vs 공개 타이밍

품질 포기는 없다. 그러나 **100강 전수 문장 검수는 공개 조건이 아니다.**  
공개 조건은 **정직성(기능 약속)·합법성(인용·라이선스)·접근(게이트 해제)·최소 길잡이(트랙)**.  
나머지 품질은 공개 후 사용자 이슈 + M4/M5로 올리는 것이 생태계에 이롭다.

## 9. CodingLabV2 평가

### 9.1 문서 실체

`ai-ops/CodingLabV2.md` (작성중 PRD, 2026-07-12):

| 블록 | 내용 |
|---|---|
| 비전 | 비개발자 대상 Vibe 코딩, 애니메이션·재미·진입장벽 |
| 핵심 기능 | ① 모션 튜토리얼 ② 단계 설명·용어 ③ **브라우저 IDE** ④ 진도 ⑤ 커뮤니티 Q&A ⑥ 접근성 ⑦ 온보딩 ⑧ 검색 ⑨ 저작권 보호 ⑩ 관리자 제작 |
| 콘텐츠 예시 | 변수·함수·조건·반복 등 **일반 프로그래밍 기초** 애니 |
| 상태 | 전 항목 ⚪ 작성중 — 구현 없음 |

OBJECTIVE가 기대한 “Claude Code / Codex / Cursor / Cline / Gemini CLI / Agent / MCP 실습”은 **이 PRD 본문에 거의 직접 등장하지 않는다.**  
반면 **현재 Master 커리큘럼**(`ai-coding-tools`, `ai-system-design`, `practical-vibe-coding`)이 그 이론 층을 **이미 텍스트로 보유**한다.

### 9.2 중복 vs 보완

| 영역 | Master (현재) | CodingLabV2 (PRD) | 판정 |
|---|---|---|---|
| 개발 원리 장문 교재 | 100강 deep | 약함(애니 중심) | **Master 고유** |
| 변수/함수 등 기초 코딩 | 모듈에 텍스트 존재 | 애니+IDE로 재학습 | **중복 위험 高** |
| AI 도구·Agent·MCP | 이론 강의 강함 | PRD에 미약 | **V2가 채워야 할 공백** (현재 PRD는 비어 있음) |
| 브라우저 IDE | 없음 | 핵심 | V2 고유 가능 |
| 커뮤니티 | 없음 | 풀 기능 | V2 후순위 (운영비) |
| 검증·인용 철학 | 매우 강함 | PRD에 약함 | **Master 철학을 V2에 이식 필요** |

### 9.3 교육 철학 연속성

- **맞는 부분:** 비개발자, Vibe 코딩 브랜드, “텍스트만으로 포기” 문제 인식, 접근성.  
- **어긋날 위험:** Master는 “빠르게 만들되 **엄격히 검증**”. V2 PRD는 “재미·애니·IDE”에 치우치면 **검증 없는 바이브**로 퇴행 가능.  
- **필수 이식:** human review, 성공 증거, 위험 경계, Master 강의 딥링크.

### 9.4 권고 순서 수정

```
[NOW]  AI Vibe Coding Master — 무료 공개 픽스 → 공개
         = 지도(Map): 원리·구조·어휘·검증 태도

[NEXT] CodingLabV2 — 범위 재정렬 후 착수
         = 운전연습(Lab): 인터랙션
         권장 포커스 피벗:
           A안(권장): AI 코딩 도구·에이전트 루프·컨텍스트·권한 시뮬
                    + 소량 기초 애니(필요 시 Master 딥링크)
           B안: 순수 코딩 기초 애니 IDE (Master와 기초 중복 감수)
         비권장: A+B+풀 커뮤니티를 v1에 동시

[LATER] Agent / Workflow / Orchestration 트랙
[FUTURE] AI Company (팀·조직·거버넌스 교육)
```

**결론:** CodingLabV2는 Master **이후**가 맞고, **보완재**여야 한다.  
현재 PRD 그대로면 **기초 중복 + AI 도구 공백**이 생긴다 → **Batch2에서 PRD 재작성(범위 피벗)을 Master 공개 픽스 다음 우선**으로 둔다.

### 9.5 V2 v1 범위 제안 (운영자 최소)

| In | Out (v1) |
|---|---|
| 미션 12~20, 애니 시뮬 3종(루프/툴콜/컨텍스트) | 풀 Q&A 포럼 |
| Master 딥링크 | 자체 100강 재생산 |

### 11.1 무료 공개해도 되는가?

**조건부 예 — GO WITH FIXES.**

§5는 공개 후에도 “최고의 무료 자료”를 향해 올리면 된다.

| 구분 | 내용 |
|---|---|
| **충분히 공개 가능** | 100강 구조, 원리 철학, 빌드 가능 정적 사이트, 검색·진도·용어, 검증 파이프라인 문화 |
| **공개 전 필수** | 인용 모드 B, LICENSE·고지, Privacy/Terms 최소, 게이트/index 전환, README·카피 정직성, 최소 학습 트랙 안내 |
| **공개 후 개선** | 도식·문장·애니·실습 카드·Analytics·계정·CodingLabV2 |

### 11.2 브랜드 구조 제안

**마스터 브랜드:** `Vibe Coding School` (가칭) 또는 현행 `AI Vibe Coding` 유지.

| 제품 | 역할 | 한 줄 |
|---|---|---|
| **Master** (현재) | Textbook | 무료 원리 교재 —  orthodoxy(정통) |
| **Lab** (CodingLabV2) | Workshop | 애니·실습 —  immersion |

### 11.3 최종 리팩토링 — 운영자가 덜 움직이게
